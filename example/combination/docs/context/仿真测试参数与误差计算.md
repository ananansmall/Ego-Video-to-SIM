## 一、被控对象总览 (为什么误差数字不能直接横比)

| | test8 | test9 | test11 |
|---|---|---|---|
| 任务 | 自主编程抓放 (轨迹写死) | MANO 轨迹跟随 | MANO 轨迹跟随 |
| 被控对象 | 虚拟 6-DOF 浮动夹爪 | 虚拟 6-DOF 浮动夹爪 | R1 右臂真机 URDF (跟踪基座) |
| 关节限位 | ±π, 实际无约束 | ±π, 实际无约束 | **真实限位** (q2∈[0,3.23], q5∈±1.66 等) |
| 工作空间 | 无限制 (平移 ±2m) | 无限制 | 有限 (臂展 0.713m, 实用 ~0.45m) |
| 轨迹来源 | 程序分段规划 | HaWoR MANO (四重平滑+EMA) | 同 test9 (共享 `_precompute_mano_targets`) |
| 夹爪位姿特征 | 手指恒朝下 (±30°) | 复现人手 (本数据集: 手指方向与竖直夹角平均 **87°**) | 同 test9 |

**核心结论**: test9 的浮动云台理论上能实现任意位姿, 它的误差是纯动力学滞后;
test11 是真臂, MANO 目标中"位置+朝向"组合经常在工作空间之外, IK 只能妥协。
**同一把尺子量不同的东西, 读数不可比。**

## 二、物理步进参数

### 2.1 GalaxeaManipSim 原始基准 (`galaxea_sim`)

| 参数 | 值 | 出处 |
|---|---|---|
| 物理时间步 timestep | **0.01s (100Hz)** | `envs/base/bimanual_manipulation.py` 默认 |
| 控制频率 control_freq | **15Hz** | 同上 |
| decimation | `int((1/15)/0.01) = 6` | `envs/base/base.py:124` |
| 驱动增益 (全部关节统一) | **stiffness=1000, damping=200** | `robots/r1.py:16-17` |
| 步进模式 | 每控制步: set_drive_target × 全关节 → decimation × {compute_passive_force(gravity+coriolis), set_qf, step} | `bimanual_manipulation.py:121-136` |
| 触摸摩擦 (4 手指 link) | (static 1.0, dynamic 1.0, restitution 0.6) | `robots/bimanual.py:140-145` |
| 手指驱动符号 | `gripper_finger_sign = [1, 1]`, action 直接作 drive target | `bimanual_manipulation.py:126-129` |
| init_qpos | 全 0 | `robots/r1.py:20` |

> 注: 我们的 `step_physics_drive()` 逐行复刻了上面这套步进模式
> (drive target → passive force → step), 模式完全一致, 数值参数不同 (见下)。

### 2.2 05_gripper_test.py (test8/9/11 共用步进)

| 参数 | 值 | 与原仓库关系 |
|---|---|---|
| 物理时间步 | 1/240s (240Hz) | 比原仓库细 4 倍, PD 步进更密 |
| 控制频率 | 30Hz | 原仓库 15Hz |
| DECIMATION | 16 | 控制周期 16/240 = 1/15s — **与原仓库控制周期一致** |
| 力补偿 | passive(gravity+coriolis) | 与原仓库一致 |

## 三、驱动增益对比 (各测试不同!)

| 关节组 | GalaxeaManipSim 原始 | test8 | test9 | test11 |
|---|---|---|---|---|
| 平移 (虚拟 x/y/z 或臂) | 1000 / 200 | 5000 / 1000 | **30000 / 3000** | 臂 **40000 / 1500** |
| 转动 (虚拟 rz/ry/rx) | 1000 / 200 (统一) | 1000 / 200 | **10000 / 1000** | (含在臂增益内) |
| 手指 (prismatic) | 1000 / 200 (统一) | 3000 / 300 | **10000 / 1000** | 3000 / 300 (沿用 test8 验证值) |

- test9 用极高刚度: 浮动云台质量小 (虚拟 link 1kg), 高增益 → 跟踪 1mm 级;
- test11 手指刻意沿用 test8 的 3000/300: squeeze 接触力 = K×Δq, 抓 25mm 方块的
  夹持力标定是按这个增益调的, 换增益会破坏抓取力标定;
- **调增益注意**: 增益影响 (a) 跟踪快慢 (mm 级), (b) 手指接触力 (N 级标定),
  两者别混为一谈。

## 四、手指关节限位 (回答"手指也得有限位吧")

**有的, URDF 层面就有**, SAPIEN 物理层强制执行:

| 来源 | limit | effort | velocity | 备注 |
|---|---|---|---|---|
| `r1_v2_1_0.urdf` (完整机身) | lower=0, upper=**0.05m** | 100 | 0.25 m/s | 原始为 fixed, 我们统一转 prismatic |
| `r1_v2_1_0_floating_right.urdf` | 同上 (0, 0.05) | 100 | 0.25 | finger1 轴 (0,-1,0), finger2 (0,1,0) |
| test8 自定义夹爪 URDF | (0, 0.05) | 500 | 0.25 | collision 用 6cm 简化 box |

**行程语义 (关键)**: q 增大 = 手指张开。
- q=0: 手指最合拢 (两指内面间隙 ≈ -3mm, 即互相过盈 3mm);
- q=0.014: 内面间隙 = 25mm, 恰好接触 25mm 方块;
- q=0.012: 间隙 20.9mm, 对 25mm 方块形成每侧 ~2mm 挤压 (test8 的 squeeze 标定);
- q=0.05: 全开 (间隙 ~97mm)。

**各测试的手指驱动目标**:
- test8: 轨迹计划 0.05→0 (边下边夹), 搬运段保持 0 (靠 K=3000 顶住方块);
- test9/test11: 直接用 MANO 解出的关节值 (`compute_mano_based_gripper_pose` 返回的 j1/j2),
  天然在 [0, 0.05] 内;
- test11 物理侧再对 qpos 做限位钳制 (qlimits ± 1e-4)。

## 五、误差计算方法 (逐 test)

### 5.1 test9 (浮动夹爪跟 MANO) — "命令 vs 实际末端位姿"

```
pos_err  = ‖cmd_pos − qpos[vx,vy,vz]‖ × 1000        (mm; 虚拟移动关节值 = 夹爪根部位置)
ori_err  = angle( cmd_R, R(eulerZYX(qpos[rz,ry,rx])) ) (deg)
joint_err = |cmd_j1 − qpos[finger1]| × 1000           (mm)
```
- 300 帧实测: **pos avg 1.1mm / max 1.9mm; ori avg 0.8° / max 3.0°; joint 0.0mm**
- 语义: 纯 PD 动力学滞后 (云台无不可达位姿)。

### 5.2 test11 (R1 臂跟 MANO) — 与 test9 同口径

```
pos_err  = ‖cmd_pos − gripper_link.world.p‖ × 1000   (mm)
ori_err  = angle( cmd_R, gripper_link.world.R )       (deg)
joint_err = |cmd_j − qpos[finger1]| × 1000            (mm)
```
- cmd 为 EMA 平滑**且经 0.45m 可达钳制后**的目标;
- 300 帧实测 (跟踪基座): **pos avg 96.9 / max 166mm; ori avg 46.9 / max 60.6°**;
- 误差构成 (实测分桶): 离基座 <0.25m 时 pos ~26mm (固定基座) / 65mm (跟踪),
  >0.25m 后跳到 150-200mm — **结构性工作空间误差, 不是量法或增益问题**;
- 已知口径注意点: 若要度量"跟手"的严格误差, 应相对**未钳制**的 MANO 原目标再算一遍
  (钳制把目标拉进了可达球, 报出来的误差是"对可达目标"的误差)。

### 5.3 test8 (自主抓放) — 不是轨迹跟随误差

- `plan_err = ‖规划基座位置 − 实际基座位置‖`: 自己跟自己的规划;
- 抓取诊断: 接触力代理 (K×Δq)、滑移相对速度、方块相对夹爪位置漂移、抓取成功率;
- 与 test9/11 的误差**不可比** (没有外部参考轨迹)。

### 5.4 指数级差异的物理解释

| 误差 | test9 | test11 | 差异根源 |
|---|---|---|---|
| pos | 1.1mm | ~85mm | test11 的 IK 妥协 (目标位姿在可达集外) + 工作空间钳制 |
| ori | 0.8° | ~47° | R1 手腕限位 q5±95° vs MANO 自由手腕 |
| joint | 0.0mm | 0-15mm | 手指驱动直接跟 MANO 值, 两边都容易 |

量法一致 (9 与 11), 差异全部来自被控对象。

## 六、平滑与可达性的关系 (常见误解)

四重平滑 (SG → 高斯Slerp → min-jerk → EMA) + 命令 EMA 保证的是**时间轴质量**:
去噪、去跳变、速度/加速度连续 → 驱动跟得住 (test11 关节误差 0-15mm 证明了这点)。
**它不改变轨迹的空间位置, 不提供任何可达性保证**。
可达性由三件事决定: 基座位姿 × 臂工作空间 × 关节限位。
处理可达性的手段见下表。

### RelaxedIK 弃用记录 (重要结论)

RelaxedIK 的解在 SAPIEN 中"位置准但朝向差 100~167°" (构型相关), 朝向伺服不可救;
且全仓库无固定基座 6-DOF 成功先例 (D4=gripper_only 浮动, 02 视频 INVALID)。
已弃用, 改用 pybullet IK (同 URDF 同约定)。pybullet IK 三个坑:
四元数直接用 scipy `as_quat()` 的 xyzw (多 roll 一次差 90°);
null-space 四件套 (limits+jointRanges+restPoses) 缺一不可;
远目标会停在 rest-pose 盆 → 多重启 + roll 扫描 + FK 残差择优。
