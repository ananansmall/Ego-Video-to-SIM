## 一、四重平滑流水线的问题

### 1.1 用户提到的方案

用户提到 "005 前置 SG 滤波 + 高斯 Slerp + min-jerk + EMA 四重平滑" 这条流水线。

### 1.2 现状: 代码里完全没有实现

经全仓搜索，`05_gripper_test.py` 中**没有**实现这条流水线。该文件里只存在两个 easing 函数，与四重平滑完全无关：

| 文件中的函数 | 实际用途 | 与四重平滑关系 |
|---|---|---|
| `_smoothstep(t)` | ease-in-out 缓动，生成机械臂抓取轨迹分段插值 | 无关 |
| `_min_jerk(t)` | 5 阶多项式缓动，机械臂运动规划零速零加速边界 | 同名但用途不同，不是对 3D 轨迹做 min-jerk |

`05_gripper_test.py` 中 `_min_jerk` 只是对标量 `t∈[0,1]` 的多项式缓动，用于"接近→抓取→抬升→释放"各阶段之间的平滑过渡，属于**运动规划**范畴；而四重平滑是针对 **MANO 参数序列**的**后处理滤波流水线**。

### 1.3 四重平滑各阶段定义（用户方案，尚未落地）

| 阶段 | 作用对象 | 当前代码是否实现 |
|---|---|---|
| 前置 SG 滤波 (Savitzky-Golay) | MANO 参数 trans/rot/hand_pose | 部分（仅在 `tools/smooth_mano.py` 单文件，未集成进管线） |
| 高斯 Slerp | 旋转四元数插值 | ❌ 无 |
| min-jerk | 3D 轨迹（指尖位置等） | ❌ 无（同名函数用途不同） |
| EMA | 关节角度 | ❌ 无（仅 `trajectory_optimization/data_loader.py` 有机器人关节 EMA，非 MANO） |

### 1.4 已落地的平滑实现（与四重平滑的区别）

`example/combination/tools/smooth_mano.py` 已实现**参数级平滑**（Kalman RW 模型 + SG），但只覆盖四重平滑的第一阶段，没有后三段：

- `smooth_mano_kalman` — Random Walk 标量模型，测量主导高增益（q=delta_mad², r=0.01·delta_mad²），MAD 异常值门控
- `smooth_mano_sg` — `scipy.signal.savgol_filter` + MAD median-clip
- `smooth_mano` — 两者 dispatcher

**关键设计决策**：axis-angle 旋转参数不做 rotate-vector unwrap（HaWoR 原始序列连续）。

`tools/test_smooth.py` 已验证：注入 15cm 尖峰后 Kalman 残差 0.58cm / SG 0.42cm（Hand0）；正常数据 RMSE Hand0 KF 4.58 / SG 2.26，Hand1 KF 2.14 / SG 0.39。

### 1.5 待确认事项

四重平滑是否属于 **规划中的功能**。若确认，需补全：SG（参数）→ 高斯 Slerp（旋转四元数）→ min-jerk（3D 轨迹）→ EMA（关节），串成 `smooth_mano_pipeline`。

## 二、对话中的澄清问题

### 2.1 相机位姿会跳变吗？只有一帧对齐吗？

**澄清结论**：
- 对齐（001_align_scene.py）产出的是**全局相似变换** `(scale_ratio, R_hand_to_glb, t_hand_to_glb)`，是**一次性**的 Umeyama 变换，**不是逐帧对齐**。
- 看到的"跳变"来自 **MANO 预测噪声**（手部顶点/关节抖动），**不是相机位姿跳变**。
- 相机轨迹本身是平滑的；跳变是手部重建结果噪声造成的。
- `render_quick.py` 的 `cam_traj_to_glb` 对相机轨迹直接套用同一个相似变换，不引入逐帧校准。

### 2.2 两种平滑方法实现了吗？

**结论**：在用户提问时**未实现**，随后在 `tools/` 实现了 Kalman + SG 两种并测试验证（见 1.4）。

### 2.3 四重平滑实现了吗？

**结论**：**没有**。`05_gripper_test.py` 只是名字碰巧有 `_min_jerk`，不是四重平滑。

## 三、render_quick.py 整体现状

> 文件: `example/combination/View/render_quick.py`
> 角色: **对齐对比查看器**（viewer），不是渲染视频管线，不做在线标定。

### 3.1 坐标哲学

规范世界 = **GLB 原生世界**（= RAS 重建世界，Z-up）。

- GLB 物体: 用 `geom.vertices` 原始顶点 = Z-up 外参/GLB 世界坐标（**不做节点变换**）。实证：数据集7 节点 T 只是导出时的 Z-up→Y-up 旋转，做了会把物体转立（z 虚高 ~0.6m），与相机轨迹不自洽。
- RAS 相机 / mask 中心 / 深度反投影: 外参原生就在 GLB 世界，直接用。
- MANO 手 / HaWoR 相机: 在 HaWoR 世界，经 `transform_params.npz` 的 `(s, R_hand_to_glb, t_hand_to_glb)` 相似变换进 GLB 世界。

### 3.2 数据加载链路

```
HaWoR npz (pred_trans/pred_rot/pred_hand_pose/pred_betas, R_c2w, t_c2w)
   │
   ├─ MANO FK (MANOLayer) → 21 关节 (j0 手腕, j16 食指尖, j20 拇指尖)
   │
   └─ 数据驱动旋转链 (无假设翻转):
        p_hawor = R_c2w_h[f] @ p_cam + t_c2w_h[f]   # 注意: 用逐帧相机位姿, 不用固定 Rx=diag(1,-1,-1)
        p_glb   = s * R_hand_to_glb @ p_hawor + t_hand_to_glb

transform_params.npz 来源: 001_align_scene.py (第一帧相机锚定 + Umeyama 尺度)
   与正统管线 00_run_pipeline.py → 002_render_scene.py 消费同一文件
```

**关键修正**：不使用固定 `Rx_hand=diag(1,-1,-1)`。那是 `R_c2w[0]≈diag(1,-1,-1)` 的第一帧特例近似，相机转动后（实测可达 34°）会产生明显漂移。

### 3.3 加载内容

| 数据 | 来源 | 说明 |
|---|---|---|
| HaWoR 相机轨迹 | `t_c2w` → 相似变换 | 深蓝 |
| RAS 相机轨迹 | `extrinsics/*.txt` → GLB 世界 | 亮绿 |
| Midpoint Raw | MANO FK (j20+j16)/2 → 相似变换 | 红/橙，未深度矫正 |
| Midpoint Depth | `*_depth_aligned.npz` → 相似变换 | 蓝/金，深度矫正后 |
| Midpoint RAS-GLB | `mano_ras_reconstruction_*.npz` joints_ras_world | 品红/青，原生 GLB 世界零变换 |
| RAS depth center | HaWoR mask 中心 → RAS 深度反投影 → GLB | 青（需 --show-depth-cloud） |
| GLB 物体 | `load_glb_objects` 原始顶点 | 方框色=GLB 原色 |

### 3.4 渲染输出

- **Matplotlib**: `_overlay.png`，固定显示范围 `[-2,2]³`，world 轴 + 相机轴箭头。
- **Plotly**: `_overlay.html` 交互式 3D。

### 3.5 用户指定的显示约束

- `[2026-08-26]` 只保留 **Midpoint** 轨迹；Wrist / Thumb / Index 标记已注释掉。
- 固定显示范围 `[-2,2]³`（自动包围盒过紧导致比例尺过大，用户指定）。

### 3.6 辅助功能（CLI）

- `--show-depth-cloud` — 开启 mask 中心 / 手腕深度反投影验证手部放置。
- `--offset-frame` / `--offset-rgb` — 对指定帧做相机→物体质心偏移对齐（调试用）。
- `--hands left|right|both` — 数据集实际只有一只手，另一只不渲染（上游 HaWoR 幻觉，不做自动判断）。
- `--no-axes` — 不画坐标系箭头。

### 3.7 与 002_render_scene.py 的关系

`render_quick.py` 是**调试查看器**，`002_render_scene.py` 是**正式视频渲染管线**（SAPIEN 渲染 + 重定位 + IK + ffmpeg）。两者消费同一 `transform_params.npz`，坐标哲学一致（规范世界=GLB 原生世界）。平滑功能目前只在 `tools/smooth_mano.py` 独立验证，**尚未集成进任一管线**。

## 五、2026-08-29 更新: 四重平滑已统一落地到 05_gripper_test.py

`05_gripper_test.py` 的 test9 现已实现完整四重平滑, 且实现已从 test9 函数内**提升为模块级统一流水线**, 供各测试复用:

| 阶段 | 函数 (均在 `05_gripper_test.py` 模块级) | 关键参数 |
|---|---|---|
| ① SG 前置滤波 (位置/关节) | `_apply_smooth_sg()` 内 `savgol_filter` | window=17, order=2, mode='mirror' |
| ② 高斯加权四元数 Slerp (朝向) | `_gaussian_quat_smooth()` (Markley 特征向量法) | sigma=5.0, window_half=9 |
| ③ min-jerk 轨迹约束 (位置三轴+关节) | `min_jerk_smooth()` (5阶多项式分段, v/a 约束) | v_max=20mm/帧, a_max=5mm/帧² (关节 1/20) |
| ④ EMA (命令级在线) | test9 主循环: `EmaTargetSmoother`(pos 0.45) + rotvec EMA(ori 0.30) + 关节标量 EMA(0.45) | 来自 `hand_track/gripper_config.py` |

- **统一入口**: `smooth_mano_trajectory(raw_pos, raw_quat, raw_joint, raw_valid, max_vel, max_acc)` — 串起 ①②③, 返回平滑后 (pos, quat, joint)。
- **备选实现**: `_apply_smooth_dai()` (do-as-i-do 风格 MAD 速度阈值 + 插值替换) 一并提升至模块级, 当前 test9 未启用。
- test9 调用链: raw(含插值补齐+anti-flip) → `smooth_mano_trajectory()` → 主循环 EMA → `set_drive_target` → `step_physics_drive`。
- 冒烟验证: 注入 15cm 尖峰的合成序列经流水线后最大帧间跳变 265mm→0.6mm, 四元数范数恒 1, 关节值保持 [0, 0.05]。
