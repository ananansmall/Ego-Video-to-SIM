# 固定底座机械臂接入Stage1/2/3实施计划

版本：F1，2026-10-02。归属[923总计划](../trajectory_optimization/docs/2026-09-23-物理仿真控制与奖励联合设计-推荐实施方案.md)任务13。
状态：代码参考核对完成，实施未开始。本轮只写MD，不改URDF/代码、不跑仿真。新模式/模块名均为设计提议，不是已支持的CLI。

## 1. 固定的到底是什么

本计划默认“固定底座”指：**机械臂底座世界位姿在每个episode内恒定，真实机械臂关节运动，夹爪随末端执行抓取和搬运。** 第一阶段采用固定安装的单臂，不同时引入移动底盘、双臂或整机躯干。

不能把夹爪整个根固定、只开合两指当作搬运方案；也不能因为URDF loader设置`fix_root_link=True`，就忽略代码每帧又`set_root_pose`移动固定根。
当前gripper_only的“固定root+虚拟六轴+手指”仍有自由末端运动能力，不等于真实固定底座机械臂。固定底座不会自动解决夹持接触/预紧问题；它增加工作空间、关节动力学与碰撞限制，须单独验证。

## 3. 目标架构与参数合同

Stage1/2/3共享TCP轨迹、夹持controller、观测及门；差别只在“末端目标如何实现”：gripper_only用既有虚拟关节，fixed_base_arm用IK生成真实关节drive target。新实现器不得重新计算另一套闭合/预紧规则。

`T_W_TCP_actual = T_W_Base_fixed × FK(q_actual) × T_flange_TCP`。
T_flange_TCP只标定一次，定义与Stage1抓取参考、Stage0对照一致；四元数顺序、左右手和单位必须显式，不用常量偏移临时补齐。

| 配置 | 首版要求 |
|---|---|
| robot_mode/side | 拟`fixed_base_arm`；side继承输入，不默认换right |
| URDF及关节映射 | 保存URDF/碰撞/inertia hash；从名称核验真实臂关节+两指，不只依赖下标 |
| 基座 | `T_W_Base`含位置和朝向，reset时设定，此后不变；固定安装位置需符合场景支撑/安装假设 |
| 夹爪/TCP | 同一手指碰撞几何、行程、轴方向、TCP定义；不使用旧测试的简化box替代 |
| 物体/场景 | 同一CoACD分片、质量惯量、摩擦、桌面、初态；其他干扰物可沿主计划隔离 |
| 控制/物理 | CPU正确性基线，统一dt/decimation；真实关节PD/力矩限制、gravity compensation明确读回 |
| IK约束 | pos/rot容差、关节限位、速度/加速度/力矩限、奇异性和碰撞阈值在运行前登记；不从旧脚本复制超大刚度 |
| 轨迹约束 | 沿用主计划相对保持门与参考偏差预算；预算分配到规划误差/IK残差/实际跟踪，不给每项各放宽一次5mm/5° |
| 成功资格 | 新robot/profile/实现器hash；旧gripper_only成功可作候选来源，不能直接移植成固定臂证书 |

新增臂与桌面/目标、自碰撞必须明确配置。目标—手指接触保留；不能为IK通过全局关闭机械臂碰撞。若首次只用单臂、无躯干，报告这个模型边界，不声称完成整机验证。

## 4. 任务13-A：离线建模和可达性，先不消耗物理

### A1 — 固定装载与实际关节合同

改动位置：`physics_env.py`的robot factory/URDF准备，关节和TCP元数据；禁止改写共享原URDF文件，生成物使用独立版本/hash。
使用fix_root_link=True的真实机械臂，不含虚拟六轴。初始q/qvel、root pose与drive targets仅在规范reset设置一次。运行中arm和fingers都通过驱动推进，不能set_qpos、设link pose或lock_root_pose。
如URDF里的臂关节在现有模型中是fixed，转换必须根据真实模型轴/限位/惯量，不把任意fixed关节都变revolute。缺动力学信息报阻塞，不用任意默认值凑模型。
验收：关节名/类型/轴/限位/FK闭环；生产step期间set_root_pose/set_qpos spy必须为0。实际root位姿漂移另记录，不能用每步重置掩盖。

### A2 — 整段参考可达，而不是仅F50可达

输入处理后的全轨迹、固定anchor、完整close/settle及任务后缀。先选一次合理安装位姿，再离线顺序IK（以前一q作seed），逐点检查所有阶段的可达性、碰撞、限位与连续性。
不只检查位置包围盒：同时检查姿态、雅可比奇异性、离散关节速度/加速度及力矩需求估计。IK解跳支或越限即拒绝；不能靠set_qpos越过去。
允许离线有界比较安装位姿，但必须预登记候选数量/安装区域和评分，最终整episode只用一个；不能每相位换基座，不能物理搜索基座来掩盖不可达。可先用1个已知合理安装位姿验证链路。
若现有MANO路径不可达，输出首不可达源帧、位置/姿态缺口与建议的最小轨迹偏差或不同安装位姿，交用户决定；不自动突破主计划偏差预算。
交付`fixed_base_reachability.json`与整段IK参考（含FK残差和限位余量）。离线IK通过不是动态抓取通过。

### A3 — 共同的末端实现器

在现有统一runner内抽离target-realization接口，拟包含reset、TCP目标→关节目标、dispatch、read_actual_tcp、read_finger_state、capabilities。保留同一物理step/子步探针，不另造fixedbase专用接触统计。
Stage2不得再以virtual_idx存在作为所有模式的硬条件；按实现器能力选择映射。gripper_only回归命令保持不变，fixed_base_arm拒绝虚拟轴/移动root操作。
实际TCP用FK/引擎link pose交叉校验，不把IK目标当实际执行位姿。所有finger q/载荷和闭合CoACD真值约定沿用现有共享控制器。

## 5. 任务13-B：Stage1→Stage2→Stage3接入

### B1 — Stage1：保留旧成功，新机器人只验固定候选

旧gripper_only的成功anchor及夹持策略继续有效地证明旧模型能力，无须重搜。将该anchor作为固定臂输入，A2先检查整个Stage1闭合/稳定/提升动作；不可达则停止，不替换成浮动夹爪子实例。
若可达，使用新实现器一次固定候选物理验证：真实关节驱动跟踪、双指载荷、相对C0保持、提升幅度。新结果属于fixed_base_arm独立profile；不能把旧成功run ID贴到新结果上。
因为动力学和接近历史已变，允许验证失败；优先分清IK跟踪/关节饱和、机械臂碰撞与原夹持问题，不默认重启48次搜索。

### B2 — Stage2：同配方和状态机，不要求照抄虚拟关节

复用同一固定臂成功动作的TCP T/q_finger/时标和控制器状态合同；臂q由连续IK及drive实现，不照抄gripper_only虚拟轴q。close/preload/settle不截尾，carry首目标/速度连续。
从规范任务初态经MANO处理后轨迹接近，比较实际TCP/目标/速度与Stage1入口；不能只比较笛卡尔命令。臂跟踪不够时先定位饱和/动力学/规划，不加物体摩擦。
优化先限定同一固定基座下的合法时间规划和主计划批准的局部TCP偏差；代价可加入关节连续性/限位/奇异性，但不得牺牲真实抓取门换取低参考误差。改变控制或轨迹后生成新hash，不混用旧证书。

### B3 — Stage3：继承真实臂状态，无reset继续

同episode继承全部真实q/qvel、控制器状态、目标状态、固定基座和C0。后缀不仅T/q_finger连续，臂q及速度也连续；不可因逐段独立IK切换到另一解支。
正式执行保留父门，诊断续行按[全流程GIF计划](../trajectory_optimization/docs/2026-10-02-全流程诊断GIF与Stage0对照计划.md)，两者产物隔离。最终严格重放从规范初态执行同一完整目标序列，不能逐帧设置记录的q_actual来代替物理。
Stage0对照使用相同固定基座/模型/TCP/IK口径，报告原参考→可达参考→实际末端三类误差；与浮动夹爪比较单列模型差异。

## 6. 任务13-C：测试、预算与分流

拟新增`tests/test_fixed_base_contract.py`、`tests/test_tcp_realizer.py`、`tests/test_fixed_base_stage_handoff.py`。先零物理测试：

1. 真实关节映射左右侧均正确；没有虚拟平移/旋转轴；URDF缺限位/惯量的处理明确。
2. reset后禁止root setter和arm qpos setter；kinematic_arm=True在物理模式入口被拒绝。
3. 已知FK/IK往返、TCP偏置/单位/四元数反例；不可达/奇异/跳支/越限命令在step前拒绝。
4. S1生产入口不生成gripper_only子实例；S2不依赖virtual_idx；S2→3实际状态/C0不清零。
5. 缺新profile证书不能把旧gripper_only证书保存成固定臂PASS；录像开关不改命令。

实施顺序：A1装载合同→A2可达性→A3实现器→B1固定候选→B2/3单episode任务→正式重放。每步有明确产物再推进。
新增物理建议最多：空载短轨迹1次、固定候选抓取1次、连续Stage2/3诊断1次，合计3次条件性资格试验，须先登记余额/确认；不是正式成功的重复验证额度。能合并或复用记录则减少，不默认凑满。无新搜索，正式重复验收另按总计划，不因“新模型”清空旧总账。

| 首失败 | 下一步 | 不做 |
|---|---|---|
| IK不可达/碰撞/关节越限 | 离线说明安装位姿或最小参考偏差需求 | 移动底座、瞬移臂、关闭所有碰撞 |
| 目标可达但实际臂跟不上 | 查dt、驱动读回、关节饱和、重力补偿、连续性；单变量修复 | 同时调摩擦、质量和anchor |
| TCP跟踪合格但夹持失效 | 回主计划g2/g3/g4检查预紧与接触能力 | 宣称固定底座自然更稳/自动重搜 |
| CPU太慢 | 用[性能计划](../trajectory_optimization/docs/2026-10-02-GPU物理与子步性能改造计划.md)分项计时 | 同次实验更换机器人、GPU、dt和碰撞几何 |

首版完成条件：底座真实固定、真实关节动力执行、完整可达性报告、阶段合同及诊断视频俱全。若抓取/搬运未通过必须标FAIL；正式成功还需同一新profile下任务07/08通过。GPU迁移在CPU合同稳定后再做，不作为先实现固定底座的必要条件。
