# Stage0 / Stage1 / Stage2 / Stage3 边界定义 + 当前测试效果

日期：2026-09-23。用途：**把各阶段的职责边界钉死**，避免"谁该做抬升/谁该做复现"再被混淆。
依据：用户 2026-09-23 原话 —— "**stage2 是负责复现原来轨迹的**，为什么现在 stage1 的抬升放到 stage2 里面呢" ✓

## 1. 边界总表（一句话版）

| 阶段 | 一句话职责 | **负责什么** | **不负责什么（易混）** |
|---|---|---|---|
| **Stage0** | **准备**：加载场景 + 预处理参考轨迹 | 物理场景（地面/桌面碰撞、各物体碰撞体、材质/质量、驱动参数）、MANO 轨迹预处理（平滑/FK）、缓存产物 | ✗ 不做规划、✗ 不做抓取、✗ 不决定成败 |
| **Stage1** | **找到一个 anchor，并带完整动作验证它** | 位姿搜索（CEM）+ **完整动作 rollout**：就位→闭合→保持→**竖直抬升 20cm** + 终验（冻结命令 ×3） | ✗ 不负责搬运、✗ 不负责沿参考轨迹走 |
| **Stage2** | **复现参考轨迹**（接近 + 按 MANO 原轨迹连续执行） | 从 anchor 出发的接近/就位、按参考轨迹的连续控制、前缀一致性判据、携带段相对位姿稳定 | ✗ **不做额外抬升**、✗ 不做"保持实验"、✗ 不重新搜索位姿 |
| **Stage3** | **连续执行**（Stage2 前缀 + 后缀携带/释放） | 同一次运行内连续重放前缀 + 后缀、携带相对位姿/进度、自然释放是否执行 | ✗ 不替代 Stage2 的前缀核验、✗ 不把"张开到位"叫精确放置 |

> **抬升归属**：**竖直抬升 = Stage1 的动作**（它本来就抬 20cm ✓）。
> Stage2/3 里**不应**再注入抬升/保持（已弃用 `_S2_LIFT_OFF_*` / `_S2_PRE_CARRY_HOLD_*` / `_S2_CARRY_HOLD` ✓，默认 0 ✓）。

## 2. 每阶段的输入 / 输出 / 通过判据

### Stage0 —— 准备
```
输入 ✓: 场景 GLB(s)、MANO 轨迹、环境变量
输出 ✓: physics 场景 (render/physics) + 预处理轨迹 + 缓存 (transform_params.npz / preprocess_traj.npz)
通过判据 ✓: 无 (只做"是否成功加载"检查)
⚠ 已知坑 ✓: 缓存会**被复用** ⇒ 沿用旧输出目录 ⇒ **复用的还是旧配置** ✗
   (实测: `_COACD_ALL=1` 必须配**新目录**才生效 ✓)
```

### Stage1 —— 搜索 + **完整动作**验证
```
输入 ✓: 场景 + 参考轨迹 (用于 enclose 等)
动作 ✓: **就位 (可选 `_S1_TRAVEL_FRAMES`) → 闭合 → 保持 → 竖直抬升 20cm**
输出 ✓: `best_grasp.npz` + `stage1_grasp_recipe.json` (anchor / 冻结 q_cmd / 实际 close-settle 时长 / 物理指纹)
通过判据 (真值验收, ≥2/3) ✓:
  lift ≥ 3cm ∧ 指尖离桌 ≥ 0mm ∧ **真夹持率 ≥ 0.5** ∧ drift ≤ 20mm
  ∧ **目标不再由桌面支撑** ∧ **夹爪未被桌面卡住/无明显穿透** ∧ 无缺测
验证方式 ✓: **三次都用同一份冻结命令** (`q_override`) ⇒ "验证动作 = 交付动作" ✓
```

### Stage2 —— **复现参考轨迹**
```
输入 ✓: Stage1 anchor + recipe
动作 ✓: 接近/就位 → 就位后闭合 (与 Stage1 同一相对构型 ✓) → **按参考(MANO)轨迹连续执行**
        ✗ 不再注入抬升/保持
通过判据 ✓: 前缀 readiness (双侧接触/就位) + 就位样本门 + `T_G_O`(物体相对夹爪) 漂移 ≤5mm / ≤5°
            + 基座跟踪误差 (mean ≤5mm / max ≤15mm) + 无碰撞过滤泄漏
```

### Stage3 —— 连续执行 + 释放
```
输入 ✓: Stage2 前缀
动作 ✓: 同一次运行内**连续**接续后缀 (不 reset、不临时切 PD、不改已验证闭合命令 ✓)
通过判据 ✓ 分别报告: ①本次前缀通过 ②后缀相对位姿稳定 ③沿轨迹移动进度 ④自然释放是否执行
```

## 4. 视频 / GIF 说明（含空 mp4 的修复）

```
录像挂载点 ✓: Stage1 `_RECORD_VIDEO_ALL=1` / Stage2 `_S2_RECORD_VIDEO=1` / GIF `_GIF_EXPORT=1`
空 mp4 成因 ✓: `_render_available=False` 时 `_record_stage2_frame` **直接 return** ✗
              ⇒ mp4 只有 44~257 字节 ✗；**并行跑录像进程**时渲染器创建失败 ⇒ 就是这种情况 ✓
本改 ✓: ① 不再静默 return ⇒ 继续尝试真实渲染 ✓ ② 首次即 WARNING ✓
使用约束 ✓: **一次只跑一个带录像的进程** ✓ (否则大概率出空视频 ✓)
有帧实例 ✓: `output/heavy1`、`output/fixf5`、`output/camfix3` = 1.3~2.4MB ✓；`fixf10` = 44B ✗
```
