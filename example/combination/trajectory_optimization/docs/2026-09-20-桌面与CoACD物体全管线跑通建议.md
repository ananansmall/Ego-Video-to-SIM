## 0. 结论

**按当前代码原样运行，我不认为 `CoACD + 真实桌面碰撞` 能稳定跑通主管线。**

这不是“再扫几个摩擦、PD、dz 参数”就能解决的问题。当前至少有以下结构性阻塞：

1. Stage1 的几何桌面是有限 `1m × 1m` AABB，PhysX 桌面却是无限平面；目标又接近该 AABB 的边缘，几何筛选可能判安全，物理仍会撞地。
2. Stage1a 只检查两根手指，不检查 `gripper_base_link`/掌部；而物理碰撞开启的是整个夹爪相关 link。
3. Stage1a 通过后，CMA-ES 与 Stage1d 会生成新位姿，却不再执行同一套桌面硬约束。
4. 没有候选通过硬约束时，代码会把失败候选重新捡回来继续优化。
5. 终选验证即使 `0/3`，仍保存 `best_grasp.npz` 并交付下游。
6. Stage1 用 `set_qpos` 把夹爪直接放到抓取位姿，不验证 Stage2 实际需要走过的接近路径。
7. CoACD 失败会静默回退 box，CoACD 参数/凸包 hash 又没有进入 recipe digest，存在“日志说跑了、实际几何不一致”的风险。

现有日志也支持这个判断：`CoACD + 无夹爪地面碰撞` 曾经 `3/3` 抬起，而
`CoACD + 开启地面碰撞` 是 `0/3`。这说明此前成功抓取至少部分依赖夹爪穿过支撑面。

因此正确顺序不是马上反复跑完整 Stage3，而是先完成下述 **P0 代码修复**。修完后再做
box/CoACD × table on/off 的对照实验，才具有归因价值。

## A. 必须先做的代码级修改

### A.1 建立唯一的“夹爪-支撑面可行性”函数

建议新增一个很小的共享模块，例如 `gripper_collision_geometry.py`，不要让 Stage1 反向从
`stage2_approach_opt.py` 导入私有常量。接口可以是：

```python
@dataclass
class GraspFeasibility:
    feasible: bool
    min_ground_clearance_m: float
    link_clearance_m: dict[str, float]
    close_axis_z: float
    reasons: list[str]

def evaluate_grasp_feasibility(
    pos, R, q_open, *, ground_z, table_collision_enabled,
    clearance_margin_m=0.001,
) -> GraspFeasibility:
    ...
```

第一版不需要上复杂 mesh distance。直接把当前已使用的指形 OBB 收拢进该模块，并补上
掌部/基座 OBB。对于无限水平面，OBB 到平面的间距可直接精确算：

```python
lowest_z = center_z - sum(abs(R[2, j]) * half_extent[j] for j in range(3))
clearance = lowest_z - ground_z
```

这个判据必须满足：

- 与 `scene.add_ground()` 一样是**无限平面**，不能再用中心 `[0,0]`、半宽 `0.5m` 的有限桌面 AABB；
- 检查左指、右指和掌部/夹爪基座，而不只是两个 finger OBB；
- `table_collision_enabled` 由碰撞作用域的唯一真源生成；当 `_NO_GRIPPER_GROUND=1` 时，不应仍偷偷加入几何桌面；
- 返回具体哪个 link、差多少毫米，不能只返回布尔值；
- 正式门槛先取 `clearance >= 1mm`，再用 PhysX 抽样标定误差，不建议一开始拍脑袋设 5mm/20mm。

然后把同一个函数接到所有会产生位姿的位置：

1. `generate_grasp_candidates_multiframe()` 生成后；
2. `cem_grasp_pose_optimize()` 的 Stage1a；
3. CMA-ES 每个 `R_actual/pos` 调用 `_eval_pose()` 之前；
4. Stage1d 每个 `p_pol` rollout 之前；
5. 终选 3 次物理验证之前和之后。

目前 `rollout_grasp_only()` 里 `_S1_TABLE_PRESCREEN` 的“两个点减固定 20mm”应删除，或只改成调用这个共享函数。不能继续保留第三套近似判据。

### A.2 修正 Stage1a 的实际错误，而不是继续调阈值

`stage1_grasp_mixin.py` 当前 Stage1a 有三个应直接修改的点：

```text
当前：始终 append 桌面 AABB
修改：仅 table_collision_enabled=True 时检查支撑面

当前：桌面 AABB 只有 x/y ±0.5m
修改：使用无限平面 min-z clearance

当前：只检查两个 finger OBB
修改：检查 palm/base + 两指，使用 q_open 对应的真实 link 位姿
```

目标物当前位置大约在 `y=-0.494m`，正好靠近当前桌面 AABB 的 `-0.5m` 边缘。因此旧判据可能因为手指越出有限 AABB 而返回“无碰撞”，但 PhysX 的无限 ground 仍会产生接触。这不是阈值问题，而是两个世界模型不一致。

### A.3 硬约束为空必须失败，禁止自动捡回失败候选

`cem_grasp_pose_optimize()` 中这段逻辑应改变：

```python
if not passed_candidates:
    # 当前代码：按 q_score 捡回 Top-K，继续跑
```

正式运行应当：

```python
if not passed_candidates:
    write_stage1_failure_report(reason="NO_GEOMETRICALLY_FEASIBLE_GRASP", ...)
    return None
```

如确实需要诊断，可加显式开关 `_STAGE1_ALLOW_INFEASIBLE_FALLBACK=1`，并强制标记
`diagnostic_only=true`；Stage2/3 必须拒绝消费这种产物。桌面不可穿透不能作为软 reward。

### A.4 Stage1 验证失败时不得保存成功 artifact

当前 `_n_pass < 2` 且已重试两轮后，只打印“带警告交付”，随后仍写入
`stage1/best_grasp.npz`。这是主管线目前最危险的控制流错误之一。

建议改为：

```python
if _n_pass < 2:
    write_stage1_failure_report(
        reason="FINAL_REPEAT_GATE_FAILED",
        verification=best_output["verification"],
    )
    return None
```

同时做两件事：

- 只有所有硬门通过后，才原子写入 `best_grasp.npz` 和 `stage1_grasp_recipe.json`；
- Stage2 加载 artifact 时必须检查 `verification.n_pass >= 2`、`diagnostic_only=false` 和 digest 一致，不能只检查文件存在。

这样才能防止同一个输出目录里的旧成功文件或新失败文件继续污染 Stage2。

### A.5 候选空间要直接生成“桌面可行位姿”，不能只围着 MANO 小抖动

当前多帧候选的姿态只围绕源帧做小角度扰动，而且代码明确没有系统处理最影响桌面可行性的局部 roll。对桌面侧夹，首先要满足：

```text
abs((R @ local_close_axis).z) <= 0.10
```

建议每个 MANO 源帧按下面顺序生成候选：

1. 先将闭合轴投影到水平面，求离该 MANO 姿态最近的桌面可行姿态；
2. 记录修正角 `mano_delta_deg`，若超过允许的 MANO 偏差，则该源帧直接不可行；
3. 只在水平闭合轴附近采样少量方位角/roll，而不是对三个欧拉角盲扫；
4. 对每个姿态先由夹爪完整几何求最低允许基座高度：

   ```text
   base_z_min = ground_z + margin - min_link_z_relative_to_base
   ```

5. 再与“手指有效接触带必须覆盖物体侧面”的高度区间求交；交集为空就不要进物理仿真。

`_GRIP_CLOSE_AXIS_HORIZONTAL=1` 可以保留作 MANO 轨迹预处理，但不应是唯一保障。最终候选和最终 artifact 都必须重新计算 `close_axis_z` 与真实 clearance。

### A.6 Stage1 的最终交付门必须包含真实接近路径

Stage1 当前直接 `set_qpos` 到抓取位姿，warmup 后闭合。这只能回答“这个静态 anchor 放进去后能否夹起”，不能回答“Stage2 能否不穿桌、不提前碰物体地走到这里”。

建议保持快速 teleport rollout 用于大批候选排序，但增加一个较慢的最终交付门：

```text
实际 Stage2 最后一段 MANO/预抓取位姿
    → q_open 下沿共享 approach path 到 anchor
    → close
    → settle
    → lift
```

该门至少检查：

- approach 全程 `gripper-ground == 0`；
- approach 全程 `gripper-target == 0`；
- close 前目标位姿漂移小于 1mm/0.5°；
- settle 双侧接触；
- lift `>=3cm` 且 `>=2/3`。

如果这个门失败，Stage1 不得交付给 Stage2。最理想的实现是让 Stage1 final gate 和 Stage2 的 approach 构造调用同一函数，避免两阶段又各写一套路径。

### A.7 CoACD 必须从“可选优化”改成“可证明的场景配置”

`data_loader.load_glb_with_physics()` 当前 CoACD 失败会回退 box。正式 CoACD 运行应增加
`require_coacd=True`（或等价配置）；当目标物分解/导出失败时直接终止，不允许静默回退。

加载时把下面信息写进 `obj_info[target]`：

```text
collision_model = coacd | box
coacd_cache_key
threshold / max_hull / resolution / shrink / flat_bottom / flat_eps_m
actual_hull_count
hull_geometry_sha256
fallback_used
```

随后把这些字段加入 `stage1_recipe.SCENE_DIGEST_FIELDS` 和 `run_metadata.json`。Stage2 只要任何一项不同就 fail-fast。

`coacd_collision.check_stability()` 也必须接到场景初始化：

1. 全部物体落地后静置；
2. 记录目标物平移/旋转漂移；
3. `>0.5mm` 或 `>0.5°` 直接失败；
4. 通过后以**静置后的 pose** 作为 Stage1/2 共同 initial pose 并写入 digest。

不要默认“64 hull 一定比 32 hull 好”。更多 hull 会带来更多接触 manifold，可能提高抖动。应在相同 mesh hash 下比较 8/16/32/64：先过静置门，再比较表面误差和抓取重复性，选择满足几何误差的最小 hull 数。

### A.8 Stage1 最终硬门应从“只看 lift”扩展为组合门

当前最终重复门只看 `lift_final >=3cm`。建议最终单次结果至少返回：

```text
geometry_feasible
min_ground_clearance_mm
gripper_ground_contact_count_by_phase
initial_target_contact
target_drift_before_close_mm/deg
bilateral_contact_ratio_settle
lift_final_cm
close_axis_z
```

单次 PASS 应是这些条件的逻辑与，而不是 lift 一项。目标物偶然被夹爪/桌面挤起 3cm，不应算有效抓取。

## B. 最小可实施修改顺序

为了避免一次改太多，我建议按下面四个 patch 分开做，每个 patch 都能独立验证：

| Patch | 修改范围 | 完成标准 |
|---|---|---|
| P0-1 几何一致性 | 新共享 clearance；无限平面；掌部+两指；应用到 Stage1a/CMA/Stage1d | 几何判断与 PhysX 抽样接触误差 `<=0.5mm`，且 table off 时不再筛桌面 |

| P0-3 可到达性 | 最终 anchor 重放真实 approach→close→lift | box+table 同一 anchor `>=2/3`，approach 零桌面/目标接触 |
| P0-4 CoACD 身份与稳定性 | strict CoACD、stability gate、digest/hash | box/CoACD digest 必不同；CoACD 无回退；静置漂移过门 |

只有 P0-1～P0-4 完成后，才值得运行本文后面的四象限与完整 Stage2/3。

## 1. 先把“桌面仿真”的口径说清楚

当前 `physics_env.setup_physics_scene()` 使用的是：

```python
scene.add_ground(ground_height, ...)
```

因此当前的“桌面”本质是 `z=ground_z` 的**无限大支撑平面**，不是有长宽、厚度、边缘和桌腿的真实桌体。

这个模型可以作为第一里程碑，验证“夹爪不能穿过支撑面”。但如果最终要验证桌边抓取、桌面局部几何或桌腿避障，应再建立一个明确的
kinematic tabletop actor，而不能继续用无限平面代替。

建议把验收拆为：

1. **Table-P0**：无限平面，只验证支撑与不穿透。
2. **Table-P1**：有限桌面 actor，验证桌边和真实空间范围。
3. **Table-P2**：如场景 GLB 本身也含桌面碰撞体，必须确保它与 `add_ground`
   不会在几乎相同的高度重复支撑，否则会产生非真实接触冲量。

本文后续的“桌面”先指 **Table-P0**。

## 2. 当前主管线的真实状态

### 2.2 标准运行配置仍然绕开了目标问题

`run_config.sh` 当前明确是：

也就是：

- 目标物用 box 碰撞体；

## 3. 目前最需要先解决的实际问题

### P0-1：CoACD 碰撞几何没有进入 Stage1/2 复用摘要

`stage1_recipe.build_scene_digest()` 目前会记录：

- `_OBJ_SCALE`；
- `_OBJ_SHAPE`；
- `_NO_GRIPPER_GROUND`；
- bbox、质量、初始位姿与物理参数。

但它**没有记录**：

- `_COACD_TARGET`；
- `_COACD_THRESHOLD`；
- `_COACD_MAX_HULL`；
- `_COACD_RESOLUTION`；
- `_COACD_FLAT_BOTTOM / _COACD_FLAT_EPS_M`；
- 实际 hull 数量与几何 hash。

这意味着 box 和 CoACD 在其他条件相同时，可能得到相同的 scene digest，Stage2 无法从 recipe 中证明它复用的真是 Stage1 已验证的碰撞几何。

**当前不改代码的应对方法**：四象限每格使用全新输出目录，严禁复用另一格的
`best_grasp.npz` 和 recipe。

**后续应修**：把上述 CoACD 完整指纹加入 scene digest 和 `run_metadata.json`。

### P0-2：Stage1 现在有两套桌面判据，且语义不一致

1. Stage1a 用两指 OBB 与桌面 AABB 做穿透硬筛；
2. `rollout_grasp_only()` 还有 `_S1_TABLE_PRESCREEN`，用“指尖点高度减去固定 20mm”做第二次粗筛。

第二套粗筛已在 `s1horiz/s1rot15` 日志中把大量 `0~4mm` 的近桌候选全部判死，而目标物高度只有约 `39.3mm`，水平侧夹时手指底部本来就必须很接近桌面。

**实验期建议**：

```bash
export _S1_TABLE_PRESCREEN=0
```

这不是关闭真实桌面碰撞；`_NO_GRIPPER_GROUND=0` 时 PhysX 桌面仍然真实生效，Stage1a 的 OBB 筛选也仍然存在。这只是先去掉一个已证明过于粗糙的重复判据。

后续应将两套判据收敛为一个 signed-clearance 真源，并用真实指形几何标定 `1~2mm` 安全余量。

### P0-3：“无候选可行”时，当前代码会绕过碰撞硬约束

Stage1a 的逻辑是：

```text
passed_candidates 为空
    → 警告“无候选通过硬约束”
    → 改为按 q_score 取 Top-K
    → 继续物理仿真
```

对无桌面的探索这种 fallback 可以用作诊断，但对“桌面不可穿透”的正式验收，这等于把硬约束自动降级了。

**当前的人工验收规则**：日志出现“无候选通过硬约束，放宽条件”时，本次直接按
**Stage1 不合格**处理，即使后面偶然抬起也不应晋级。

**后续应修**：正式模式 fail-fast；只在显式 diagnostic 模式允许 fallback。

### P0-4：初始候选检查了桌面，但 CMA-ES/Stage1d 没有使用同一几何硬约束

Stage1a 的初始候选有 OBB 桌面检查，但后续 CMA-ES 主要依赖 MANO 5° 约束与物理 reward，Stage1d 又会扫描新的平移位姿。

因此“种子不撞桌”不等于“最终 anchor 不撞桌”。正式解法应是将同一个几何可行性函数应用到：

- Stage0 候选；
- Stage1a 排序；
- CMA-ES 每个样本；
- Stage1d 平移精修；
- 最终 3 次验证门。

### P0-5：CoACD 有稳定性检查函数，但主管线未调用

`coacd_collision.check_stability()` 已经实现了默认 `0.5mm / 0.5°` 的静置准入判据，但全仓库没有调用点。

Stage2 确实会做静置，但目前的逻辑主要是记录与重新取参考位姿，不是“CoACD 几何不稳定就拒绝进入 Stage1”。

实际上，CoACD 几何的准入门应发生在最早的场景加载之后，而不是到 Stage2 再用重置吸收它的初始翻滚。

### P0-6：姿态是桌面可行性的核心，不能只调 z

目标物高度约 `39.3mm`，指形 z 方向包围半尺寸约 `18.5mm`。如果闭合轴水平，理论上存在桌面上侧夹取空间；但如果闭合轴竖直度约 `0.70`，一个手指必然朝桌面下方走。

因此：

- `_GRIP_CLOSE_AXIS_HORIZONTAL=1` 应成为桌面运行的必备配置；
- 验收时要直接检查 `abs(close_axis_z)`，建议首轮要求 `<=0.10`；
- 不应再通过单独抬高 anchor z 解决问题，因为抬高后可能根本包不住只有 39mm 高的物体。

### P1-1：Stage2 能记录桌面接触，但尚未形成完整的分相验收

当前 `ground_contact` 被记录，但“接触地面”在不同相位的语义不同：

| 相位 | 夹爪↔桌面 | 目标物↔桌面 |
|---|---|---|
| reset / MANO_FOLLOW / approach | 必须无 | 应有支撑，但不得被推动 |
| close / settle | 必须无 | 可以从有支撑过渡到离桌 |
| carry | 必须无 | 必须无，否则不是真抬起 |
| release | 根据任务 | 落桌或落入容器时可以有 |

后续不应只保存一个 `ground_contact: bool`，而应保存具体 pair，至少分开
`gripper-ground` 和 `target-ground`。

### P1-2：暂时不要同时恢复非目标物碰撞

用户当前的目标是“桌面 + 目标物 CoACD”。现有 `stage1_target_isolated` scope 仍会关闭：

- gripper ↔ non-target；
- target ↔ non-target。

建议本轮先保持这一点，只恢复桌面，不要把邻物碰撞也同时打开。否则试验从两变量变成三变量，失败结论仍然不可归因。

## 4. P0 修复后再做的四象限实验

必须先说明：**当前代码下这不是严格的四象限。** 即使
`_NO_GRIPPER_GROUND=1`，Stage1a 仍无条件加入桌面 AABB；反过来，即使 Stage1a 判定不撞有限
AABB，PhysX 无限 ground 仍可能发生碰撞。因此当前 A/B 只能作为物理碰撞关闭时的诊断，不能作为“无桌面几何约束”对照；C/D 也不能证明几何筛选与真实桌面一致。

下面实验应在 A.1～A.4 至少完成后执行。若今天只做不改代码的运行，建议止于复现和保存日志，不建议继续把参数扫描当作跑通方案。

### 4.1 修复后的首轮公共参数

先以 `run_config.sh` 的 scale、PD、摩擦、q_open、轨迹参数为唯一基线，只额外明确以下实验参数：

```bash
source run_config.sh

export _STAGE1_CEM_REF=anchor

export _COACD_MAX_HULL=64
export _COACD_FLAT_BOTTOM=1
export _COACD_FLAT_EPS_M=0.0015

# 首轮不用 CoACD 分数重排候选，先只测真实物理差异

export _S1_COACD_RERANK=0
export _S1_COACD_PENALTY=0
```

这套配置只用于修复后的首轮回归；其中 `_S1_TABLE_PRESCREEN=0` 表示旧粗筛已停用，新的共享 clearance 硬门仍必须开启。这套配置的意义是：

- 多帧候选真正按各自源帧约束；
- 闭合轴先保证水平；

- 候选排序暂时不被新的 CoACD 软分改写，避免同时调优化目标。

## 5. 每一阶段的明确验收条件

### 5.1 场景与 CoACD 加载门

| 指标 | A | B | C | D |
|---|---:|---:|---:|---:|
| target collision shape 数 | 1 | 64 | 1 | 64 |
| CoACD 日志 | 无 | 参数、cache key/分解结果、hull 数齐全 | 无 | 参数、cache key/分解结果、hull 数齐全 |
| 静置漂移 | `<0.5mm / <0.5°` | `<0.5mm / <0.5°` | `<0.5mm / <0.5°` | `<0.5mm / <0.5°` |
| 夹爪↔桌面 pair | OFF | OFF | ON | ON |

如 B 或 D 的日志显示“CoACD 不可用，回退 box”，本次不能算 CoACD 试验。

### 5.2 Stage1 门

建议正式记录以下值：

- 候选总数、MANO 约束剔除数、桌面/障碍物剔除数、最终可行数；
- **最终可行候选必须 `>0`**，不允许走“无候选后放宽”fallback；
- `abs(close_axis_z) <= 0.10`；
- 夹爪对桌面 signed clearance 建议 `>=1mm`；
- q_open 入口不得已接触目标；
- 闭合前不得推动目标物；
- `lift_final >=3cm` 的重复次数 `>=2/3`；
- 作为稳定基线，最好三次都能抬起 `15cm` 以上，而不只是刚过 3cm 门槛。

### 5.3 Stage1 transfer 门

- 三次独立 reset；
- 入口无目标接触；
- settle 窗口保持双侧接触；
- `>=2/3 PASS`；
- 不允许 Stage1 通过、transfer 0/3 时继续调 Stage2 轨迹。

### 5.4 Stage2 门

除了现有 gate，本轮应额外把以下项当作人工硬门：

- `INITIAL_TARGET_CONTACT = false`；
- `RESET_DRIFT` 满足更严的 CoACD 准入标准，不要只看现有 12mm/2° 业务门；
- MANO_FOLLOW / APPROACH / FINAL_APPROACH 期间 `gripper-ground = false`；
- APPROACH 期间 `target_contact = 0`。当前它在代码中是软指标，但这次验收不应放过；
- settle 段双侧接触持续；
- carry 段 `target-ground = false`；
- `T_G_O <=5mm/5°`；
- tracking `mean<5mm / max<15mm`；
- 三次重复 `>=2/3 PASS`。

### 5.5 Stage3 门

- 必须消费同一输出目录中已通过的 Stage2 bundle；
- Stage3A：`max T_G_O <=10mm`，双侧接触比例 `>=0.80`；
- Stage3B：夹爪张开到位；
- 全程 `gripper-ground = false`，除非后续任务明确设计了夹爪接触桌面的动作；
- 不得用 `_S3_DIAG=1` 的诊断结果冒充 PASS。

## 6. 四象限结果的解读方法

| A | B | C | D | 结论 |
|---:|---:|---:|---:|---|
| FAIL | — | — | — | 新规范化配置自身不稳，先不要谈 CoACD/桌面 |
| PASS | FAIL | PASS | — | CoACD 几何/接触是主因 |
| PASS | PASS | FAIL | — | 桌面可行姿态或轨迹是主因 |
| PASS | PASS | PASS | FAIL | CoACD 底部与桌面、或 multi-hull 接触冲量存在耦合问题 |
| PASS | PASS | PASS | PASS | 才可以宣布 Table-P0 + CoACD 管线跑通 |

如果 D 失败，先按**第一个 gate failure**分类，不要同时搜 dz/dq/摩擦/PD：

- `RESET_DRIFT`：查 CoACD 落地、底部压平、hull 自重叠与双层支撑；
- `INITIAL_TARGET_CONTACT`：查 anchor 与 q_open，不要加大摩擦；
- `PRE_F50_READY`：查接近段桌面/目标几何和 PD 跟踪；
- `PROVISIONAL_GRASP`：查闭合轨迹、CoACD 夹持面与对中；
- `CARRY`：查双侧接触持续性和 T_G_O，不要先放宽门槛；
- `COLLISION`：先确认接触 pair 是 gripper-ground、target-ground 还是 non-target leak。

## 7. 后续真正值得改的最小代码集（本次不改）

按优先级排序：

1. **补全几何指纹**：CoACD 完整参数、cache key、实际 hull 数、hull 几何 hash 进 recipe digest 和 metadata。
2. **接入 CoACD 准入门**：加载后、Stage1 前调用稳定性检查；不达标应 fail-fast，正式模式不应静默回退 box。
3. **统一桌面几何函数**：用同一 signed-clearance 实现候选、CMA-ES、Stage1d 与最终 gate，删除固定减 20mm 的粗筛。
4. **禁止正式 fallback**：桌面硬约束下无候选时立即报错，不再捡回不合格 Top-K。
5. **分开接触 pair**：明确保存 `gripper-ground` 与 `target-ground`，并按 phase 建门。
6. **姿态先、位置后**：先在水平闭合轴可行集中选方位，再搜索 3D 位置；不要让上下夹姿态靠抬得起获得高分。
7. **Top-K 去重与多样性**：不要让 6 个几乎相同的姿态占满物理验证预算；应按源帧、姿态角和位置聚类后取代表。
8. **最后再做有限桌面**：Table-P0 通过后，用单一明确的 kinematic tabletop 替换无限 ground，避免支撑面重复。

## 8. 我认为最实际的执行优先级

### 第一优先：先让 C 通过

**C = box + 真桌面** 是最有信息量的下一步。

这里的前提是先完成 P0-1/P0-2，使几何筛选和 PhysX ground 一致，并让失败控制流真正 fail-closed。否则继续跑 C 只是在已知不一致的模型上碰运气。

原因：

- box 的抓取接触已经有多个全管线成功基线；
- 如 C 都不通，说明首要矛盾是“抓取姿态 vs 桌面”，而不是 CoACD；
- 只有 C 通过后，D 失败才能明确归因到 CoACD 与桌面的耦合。

### 第二优先：让 B 稳定到 3/3，而不是偶然 1/3

最新 CoACD 日志中已经出现同一 anchor 的
`[0,0,21.8]cm`，说明它不是完全不能抓，而是方差大、处在边界。

所以 B 的目标不应是“跑出一次 20cm”，而应是“同一 anchor 至少 2/3，最好 3/3”。

### 第三优先：最后合并到 D

D 首次合并时，不要再改其他参数。如果失败，回到 B/C 对照同一指标，只修一个根因。

## 9. 最终宣布“跑通”的标准

我建议只有同时满足以下条件才宣布完成：

1. `_COACD_TARGET=glb_4`，且 geometry manifest 证明实际加载了经稳定性验证的 CoACD hull，没有回退 box；hull 数不预设必须是 64；
2. `_NO_GRIPPER_GROUND=0`，且 collision scope 证明 gripper-ground pair 真实开启；
3. Stage1 有非空几何可行集，未走硬约束 fallback；
4. Stage1 `>=2/3 PASS`，最终 anchor 闭合轴水平且夹爪不穿桌；
5. Stage1 transfer `>=2/3 PASS`；
6. Stage2 `>=2/3 PASS`，接近段无目标/桌面接触，carry 段目标已离桌；
7. Stage3A/B 都 PASS；
8. 三视角视频与数值 trace 一致，没有“视频看似穿透、数值却 PASS”；
9. 使用全新输出目录，且 recipe/metadata 能证明整条管线使用同一套几何与物理参数。

## 10. 简短版建议

1. **当前版本不能认为会稳定通过**；不要直接跑 CoACD+桌面的 Stage3。
2. 先统一无限平面 clearance，并覆盖掌部+两指、Stage1a、CMA、Stage1d 和终选门。
3. 候选为空或终选 `<2/3` 时必须失败，不得 fallback，也不得保存 `best_grasp.npz`。
4. Stage1 最终交付前必须重放真实 approach→close→lift，不能只靠 teleport 抓取。
5. CoACD 必须 strict load、静置准入，并把实际 hull hash/参数写进 digest。
6. 完成上述 P0 后，先让 **C: box+桌面** 通过，再稳定 **B: CoACD+无桌面**，最后合并 D。
7. 当前最不值得做的是继续扫摩擦、PD 或单独 dz；它们无法修复几何模型和失败控制流不一致。
