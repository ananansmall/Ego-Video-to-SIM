### 2.3 夹爪几何模型（务必记住）


## 3. 本轮改动明细

### 3.1 【P0】渲染完整性 —— 静默失败改响亮报错 + 帧数断言

**背景**：用户反馈"只渲染 0-90 帧，最后跟随夹爪的轨迹没渲染成功"。

**查明**：
1. **渲染其实是完整的** —— 149 帧覆盖全程。画面左上角 `src F90.00` 是**源帧索引标签**（MANO 轨迹 0-90 帧），**不是视频帧数**。
2. **但确实有一处真隐患**：`_record_stage2_frame` 里 writer 为 `None` 时**静默 `continue`** → 一帧不录却毫无提示。

**改动**（`stage2_reconstruct_mixin.py`）：
- `writer/camera` 缺失 → **首次遇到就 `logger.error`**（只报一次，不刷屏）
- 新增 `self._stage2_frames_written` 计数（按 `index == 0` 重置，与调用结构解耦）
- rollout 末尾断言：**录制帧数必须 == timeline 控制点数**，不符则 error

```python
if _written == _expected:
    logger.info("[Stage2 render] 已录制 %d 帧 = timeline %d 控制点 ✓", ...)
else:
    logger.error("[Stage2 render] ★ 录制帧数不符: 实际 %d vs %d ...", ...)
```

### 3.2 【P3】接近段平滑衔接 —— 修速度断崖

**用户反馈**："到达接近段就停下来，然后再到目标位姿，不连续"。

**根因**（实测）：
```python
src_for_pose = f_start + (F50-f_start) * _smoothstep5(progress)
```
`smoothstep5` **两端导数都是 0** → 从前缀 `MANO_FOLLOW`（重放人手轨迹，**有速度**）切入接近段时，
**速度从非零突降到 0** → 视觉上就是"先停住、再重新起步"。

**修复**：新增 `_hermite_blend(t, m0, m1)`（`stage2_reconstruct_mixin.py:149` 附近）
```python
s(t) = h10·m0 + h01 + h11·m1     # s(0)=0, s(1)=1, s'(0)=m0, s'(1)=m1
```
- `m0 = 前缀末端速度 / 接近段平均速度`（**起点与前缀速度连续**）
- `m1 = 0`（**终点停稳**以便闭合手指）

**实测日志**：
```
[Stage2 timeline] 接近段速度衔接: 前缀末端 1.000 源帧/控制点 vs 接近段平均 0.500
                                   → Hermite m0=2.000  (0=原先的起步即静止)
```

### 3.3 【P2】scale 0.45→0.8 + 夹爪开合限制

**开度规则**（`stage1_recipe.py` 新增 `q_open_for_object_width`）：
```python
指缝 = 0.010 + 2q  ⇒  q = (MULTIPLE × W - 0.010) / 2
Q_OPEN_OBJECT_MULTIPLE = 1.20      # 默认 20% 余量
Q_OPEN_LIMIT = 0.070               # 硬上限（URDF 上限 0.075 留 5mm）
```

**优先级**：`_Q_OPEN` 环境变量 > 按 `object_width_m` 自动计算 > 历史默认（0.05）

**★ 关键教训 —— `object_width_m` 必须传"物体在夹爪闭合轴上的实际投影跨度"，或其保守上界。**
**绝不能传 GLB 局部系的 bbox 宽度**（物体带姿态，局部 bbox 与投影可差很多）：
- scale=0.8 实测：局部 bbox y = 89.4mm，但日志实测 `物体|y|max = 60.1mm`（跨度 120.2mm）
- 结果虎口内侧 60.4mm 只比物体大 **0.3mm** → 手指撞穿 11.4mm、跟踪被顶开 24.4mm → `PRE_F50_READY` FAIL
- **保守上界取 bbox 对角线 √(x²+y²+z²)**，它对任意朝向都不小于真实投影跨度

### 3.4 【N-5】接近段避让优化器 —— 几何模型三次迭代

N-5 给接近轨迹叠一条横向偏移曲线来绕开物体（`stage2_approach_opt.py`）。
**这一轮把它的几何模型从"错得离谱"修到"与物理一致到 0.2mm"。**

| 版本 | 手指模型 | 问题 | 症状 |
|---|---|---|---|
| ① | 世界系轴对齐盒 | 忽略手指随夹爪旋转 | 报"无穿透"而物理穿透 2.98mm |
| ② | 沿手指轴的球串 | **球半径受最长轴支配**，无法表达 10mm 薄板（厚度方向多外扩 11.5mm） | 报幻影穿透"16.50mm 修不动" |
| ③ | **OBB（有向盒）分离轴测试** | ✅ 无外扩、姿态精确 | **物理实测校验误差 0.2mm** |

**OBB 校验数据**（`obb_obb_signed` / `obb_aabb_signed`）：
```
q_open=0.070   → 穿透  0.00mm ✓
q_grasp=0.0282 → 穿透 11.50mm   vs 物理实测 11.70mm   (误差 0.2mm)
q=0.0200       → 穿透 19.70mm   解析期望 19.70mm      (完全一致)
```

**偏移曲线基函数**也改了（`sin(πu)` → `sin²(πu)`）：
- 旧版 `δ'(0) = a·π ≠ 0` → 偏移一启动就带速度突跳
- 新版两端导数都为 0 → 起止速度连续，峰值仍在 u=0.5

**代价函数**：
```
总代价 = C_collide + C_follow + C_feasible
         ↑穿透+3mm安全余量  ↑偏离原轨迹幅值(归一化到30mm上限)  ↑越界重罚
```

### 3.5 【Stage3】搬运减帧

## 5. scale 调整：物理上限分析 + 当前卡点

### 5.1 物理上限（结论：**不是物理架不住**）

| 量 | 值 |
|---|---|
| 虎口内侧可达上限 | `0.005 + 0.070(Q_OPEN_LIMIT) = 75mm`（按 0.075 极限则 80mm） |
| 物体在闭合轴的投影跨度 | `75.1 × scale`（mm）〔由 scale=0.8 实测 60.1mm 反推〕 |
| **可夹规模上限** | **scale < 1.0**（75.1×1.0 = 75.1mm ≈ 75mm） |

**⇒ 夹爪容量支持到 scale ≈ 0.95~1.0，物理层面完全架得住 0.8。**

### 5.2 当前卡点：**接近路径真的穿过物体**（非幻影）

scale 0.7 实测（姿态已正确传入）：
```
[N-5][名义几何] 目标=glb_4 姿态=target_actor bbox=[0.0629, 0.0782, 0.055]
[N-5] 接近段优化: 穿透 19.54mm → 18.71mm (偏移 a_y=3.6mm, a_z=-12.3mm)
Stage2: FAIL(PRE_F50_READY) tracking=3.39/17.92mm   ← 均值达标, 最大值 17.9 > 15
```

**⇒ 这个 19.5mm 穿透是真实的**：MANO 人手轨迹的接近路径**确实穿过物体**（轴向逼近只后退 0.11m）。
- scale 0.45：物体投影 33.8mm，虎口 55mm → 余量 21.2mm ✓ 够用
- scale 0.7：物体投影 52.6mm，虎口 68.7mm → 余量 16.1mm，但**路径横向位置**使得手指前面撞上物体 ✗

### 5.3 scale 继续推进的方案（按代价从低到高）

| # | 方案 | 做法 | 预期 |
|---|---|---|---|
| **A** | **加大轴向后退距离** | `--stage2-approach-start-m` 0.16 → 0.22~0.28 | 让接近段有更长的避让走廊 |
| **B** | **按物体尺寸自适应后退** | `approach_start_distance` 与物体投影跨度联动（类似 N-5 搜索范围的做法） | 一次改动覆盖所有 scale |
| **C** | **允许 N-5 偏移在终点非零** | 目前 `sin²` 基函数在 u=1 处为 0（终点不可偏移）；若放开终点约束，可绕开"必须从正前方插入"的限制 | ⚠️ 会改变抓取位姿，需重跑 Stage1 |
| **D** | **N-5 搜索范围再放大** | 当前 `R = max(0.050, 0.75×物体最大尺寸)`，scale 0.8 时为 ±98mm；若偏移已到边界则继续放大 | 边际收益待验证 |

**⇒ 建议先做 A（一行命令即可测），确认有效后做 B（自适应）。**
