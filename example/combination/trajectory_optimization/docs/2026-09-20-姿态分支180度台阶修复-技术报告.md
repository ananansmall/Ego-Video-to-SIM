> §1–§9 是"180° 台阶"的定位与修复记录；**§10 是后续追加的"抖 / 开合不对"独立诊断与修复**（两条症状其实与台阶无关，见该节）。

**根因是两层**：
1. `align_gripper_approach_to_gravity` 用 `dot(X,g) < 0` **逐帧、无状态、硬阈值**决策翻转。当 approach 轴接近水平时，相邻帧间该符号随机跳变 —— 实测台阶处 `|X_raw.z|` 均值仅 **0.0046**，即**把 1° 量级的过零噪声放大成了 180° 台阶**。
2. **决定性发现**：闭合轴水平化（绕 X 转 θ，实测 θ = **−60° ~ −123°**）与分支翻转（绕 Y 转 180°）**不可交换**。先水平化会让台阶从"绕 Y 180°"变成"绕 Z 180°"，于是"绕 Y 翻转"这个对症解**完全失效**。⇒ 必须"先定分支，再水平化"。

**修复** = 新增 `physics_utils.track_rotation_branch`（整段 Viterbi/DP 选分支）+ 把预处理链路重排为**三层**：`只定分支 → 分支 DP → 闭合轴水平化`。

## 1. 问题现象

`output/*/preprocess_traj.npz` 的 `grip_R`（svd_palm 解算出的夹爪姿态序列，113 帧）：

```
帧间姿态变化: mean=4.34°, max=179.38°, >90° 帧对 2 处: F11 / F109
```

`F10 → F11` 的实测数据：

| | F10 | F11 |
|---|---|---|
| `R_raw.X`（未做重力对齐） | `[+0.487, +0.873, **+0.0069**]` | `[+0.513, +0.859, **−0.0039**]` |
| 帧间 raw 变化 | — | **≈1.2°（平滑）** |
| `R_final.X` | `[−0.487, −0.873, −0.0069]`（**被翻**） | `[+0.513, +0.859, −0.0039]`（没翻） |
| 帧间 final 变化 | — | **179.38°** |

⇒ `X_raw.z` 只从 `+0.0069` 过零到 `−0.0039`（**0.01 的抖动**），硬阈值把它放大成 179° 台阶。

**下游危害**（历史实测，已有记录）：1 个控制周期（33ms）内命令翻 180°，PD 跟不住 ⇒ `[Stage2 track] MANO_FOLLOW rot=17.51/**169.02deg**`，即画面里"夹爪反了/朝上了"。

## 2. 定位方法（可复现）

### 2.1 判定"哪一帧被翻过"

把 `data_loader.align_gripper_approach_to_gravity` monkeypatch 成恒等，用**同一份 `joints`** 复算未对齐的 `R_raw`，再逐帧比对：
`dot(R_final.X, R_raw.X) < 0` ⇒ 该帧被硬阈值翻过 180°。

工具：`tmp/vis_svd_mapping_check.py`（只读诊断 + 渲染）。

### 2.2 根因量化（104 份历史运行）

```
台阶处 |X_raw.z| 均值 = 0.0046      ← ≈0，纯过零噪声
raw 最大朝上量        = 0.179        ← 头部/尾部 15 帧
```

## 3. 根因（两层）

### 3.1 逐帧硬阈值 ⇒ 过零抖动

```python
# physics_utils.align_gripper_approach_to_gravity —— 改动前
if float(np.dot(R[:, 0], g)) < 0.0:      # 无状态、逐帧、硬阈值
    R = R @ np.diag([-1.0, 1.0, -1.0])   # 绕开合轴 Y 转 180°
```

当 `|dot(X,g)| ≈ 0.005` 时，翻与不翻**物理上等价**，但该判据每帧独立抛硬币。

### 3.2 ★ 决定性发现：水平化与分支翻转**不可交换**

`_GRIP_CLOSE_AXIS_HORIZONTAL=1` 时 `align_gripper_approach_to_gravity` 之后还会绕 **X** 转 θ 把开合轴旋进水平面。实测 θ 不是小角度，而是 **−60° ~ −123°**。

| 水平化 | `F10→F11` 相对旋转 | 翻分支后台阶 | `\|Y·z\|` |
|---|---|---|---|
| **关** | 绕 **Y** 180°（分支翻转是对症解） | 178.8° → **2.3°** ✅ | 0.836（上下夹 ❌） |
| **开** | 绕 **Z** 180°（残差 1.69°） | 178.3° → **180.0°** ❌ | 0.000 ✅ |

⇒ 这解释了为什么"先水平化再修分支"一定失败，也解释了历史上为什么老 npz 上离线 DP 反而看似有效（旧管线里 `patch#4` 把 98 帧 roll 过，恰好把结构改回"绕 Y"）。

**正确顺序 = 分支决策必须在水平化之前。**

## 4. 修复方案

### 4.1 三层链路

```
① 逐帧解算 (horizontalize=False)   → 序列里只剩"绕开合轴 Y 的 180° 分支差"
② track_rotation_branch (整段 DP)  → 全局最优分支, 台阶 → 0
③ horizontalize_closing_axis       → 开合轴最后统一落进水平面 (|Y·g| = 0)
```

代码入口：`GraspSimulator._apply_branch_dp()`（`grasp_hawor.py`），被 `run()` 预计算与 v4 路径**两条轨迹构建链**共同调用。

### 4.2 DP 代价模型

每帧两个**等价**候选分支（绕开合轴 Y 转 180°：`X→−X`、`Z→−Z`、**`Y` 逐位不变**）：

```
状态   : {0: R, 1: R @ diag(-1,1,-1)}
代价   : ① 帧间测地角                  (换分支天然 +~176°)
         ② switch_penalty_deg = 30     每次换分支额外罚
         ③ up_penalty = 30 × relu(−X·g) X 朝上罚
硬约束 : |dot(X_raw,g)| > hard_tilt(0.5) 的帧必须 X 朝下
锚     : anchor_idx 锁 X 朝下 (默认取 |dot(X_raw,g)| 最大的帧, 本数据 = F49)
```

**为什么能修好**：近水平的帧（`|X·g|≈0.005`）翻与不翻代价几乎相同（朝上罚≈0.1），而切换一次要 ~180° ⇒ DP 自然"保持与邻帧连续"；方向明确的帧被硬约束钉死朝下 ⇒ 语义不丢。

### 4.3 代码改动清单

| 文件 | 改动 |
|---|---|
| `physics_utils.py` | **新增** `track_rotation_branch()`、`rotation_step_deg()`、`rotation_traj_diag()`；**抽出** `horizontalize_closing_axis()`；`align_gripper_approach_to_gravity()` 新增 `horizontalize=None` 形参（`None` = 读环境变量 ⇒ **默认行为逐位不变**） |
| `data_loader.py` | `compute_mano_based_gripper_pose()` / `compute_analytical_gripper_pose()` 透传 `horizontalize`；**新增** `gripper_pos_for_branch()`（分支翻转后重算 `pos`） |
| `grasp_hawor.py` | **新增** `_apply_branch_dp()`；两条轨迹构建链：解算传 `horizontalize=False` → 调 `_apply_branch_dp()`；`_dump_preprocess_traj()` 落盘 `R_branch` / `R_diag` |
| `stage2_reconstruct_mixin.py` | `_GRIP_FORCE_DOWN` 块与分支 DP **二选一**（DP 开启时降级为只诊断，否则会把 DP 有意保留的近水平帧翻回去） |
| `run_config.sh` | 新增 `_ROT_BRANCH_DP=1`（含原因/回退说明） |

## 7. 边界与后续

### 7.1 `X` 朝下 100% → 86.7% 是**有意取舍**

15 帧（F0–F10、F109–F112，手入画/出画）的 raw approach 轴本身就几乎水平（`X_raw.z = +0.004 ~ +0.179`，即与水平面差 79°~90°）。此时：

- 强行"朝下" ⇒ **必然**产生 180° 台阶（raw 过零，无解）；
- 保持连续 ⇒ 这 15 帧 `X` 最多朝上 10.3°，但整段帧间变化 ≤3.35°。

DP 选择后者（代价模型自动得出，`up_penalty` 在 10~100 区间结果一致）。

⇒ **建议把验收门 #1 从"X 朝下占比 = 100%"修正为**：
> `|X·g| > 0.17` 的帧必须 100% 朝下；`|X·g| ≤ 0.17`（模糊带）以连续性为准。

### 7.2 建议新增的硬门（Phase 3，未实施）

在 Stage1a 预筛 + Stage2 契约门同时检查：
```
|dot(Y, ĝ)| ≤ 0.35        且     dot(Y_cand, Y_ref) > 0
```
让"上下夹/翻转解"根本进不了候选集，而不是靠 `stage1_reward` 的软项清零止损。

### 7.3 待清理（Phase 5，未实施）

`mano_smoothing.smooth_gripper_traj` → `unflip_rotation_traj_continuity` 这条链**仍是死代码**（`_smooth_mano_traj` 全仓无调用点）。现已由分支 DP 取代，建议接线成断言或删除，避免下次又"以为在跑"。

### 7.4 上游（Phase 4，未实施）

`physics_utils.flip_mano_hand_down`（幂等，旋转非镜像）可在上游修正 MANO 手姿态，让 approach 轴天然朝下。但它改的是 Stage0 映射本身 ⇒ 需重跑 Stage1，建议单独一个变量做。

## 8. 用法 / 回退

```bash
source run_config.sh          # 已含 export _ROT_BRANCH_DP=1
```

| 开关 | 行为 |
|---|---|
| `_ROT_BRANCH_DP=1`（默认） | 三层链路 + 落盘 `R_branch`/`R_diag`；Stage2 的 `_GRIP_FORCE_DOWN` 自动降级为只诊断 |
| `_ROT_BRANCH_DP=0` | 完全回退到旧行为（逐帧硬阈值 + `patch#4` + `_GRIP_FORCE_DOWN`），用于 A/B |
| `_GRIP_CLOSE_AXIS_HORIZONTAL=1` | 闭合轴水平化；DP 链路下由第③层统一施加（不再逐帧内部施加） |

## 9. 一句话总结

180° 台阶不是"解算错了"，而是**在等价解之间逐帧抛硬币**；而且真正的坑是**水平化（绕 X θ≈−120°）与分支翻转（绕 Y 180°）不可交换**，所以任何"先水平化再修分支"的方案都注定失败。
修复 = 把分支从"逐帧硬阈值"提升为**整段 DP 的显式状态**，并把链路重排为 `只定分支 → DP → 水平化`；104 份历史数据回归 **台阶 206 → 0，最大帧间跳变 179.6° → 3.3°**，`det/正交/Y 一致性` 全部保持。

## 10. 【追加】"轨迹一抖一抖"与"两个动图开合都不对"的独立诊断

> 触发: 用户看完 stage0 视频后的反馈 —— "修复后的轨迹怎么一抖一抖的，而且两个左右的动图开合都不对"。
> **结论先说**: 这两条**都不是** 180° 台阶造成的，也**不是同一回事**；其中"抖"由 §10.3 的符号错误造成（已修），"开合不对"里有一部分是**输入数据的固有属性**（管线内无解）。

### 10.1 "开合量不动" —— HaWoR 数据本身手指几乎不动（两版完全相同）

直接打开原始 HaWoR 重建（`/home/an/data/hawor/7a`，**不做任何平滑**）做 MANO FK：

```
捏合开合 |拇指尖 j4 − 食指尖 j8| = 5.94 cm，全序列只在 [5.42, 6.17] 之间变化 → Δ = 0.75 cm
pred_hand_pose 逐帧 std = 3.93°   （|值|mean = 17.35°）
腕→食指尖 帧间 std = 0.15 cm
```

管线输出与之**逐位一致**（15.13cm / Δ1.86cm，缩放比 2.5458 → 5.94cm / Δ0.73cm），且
`joints_raw`（平滑前）与 `joints`（平滑后）的捏合开合量**完全相同** ⇒ **不是平滑抹掉的，是数据本身**。

后果：命令开合 `j1` 恒在 **0.0221–0.0258**（全序列只变 **3.7 mm**），夹爪开口恒在 **5.4–6.2 cm**，
从头到尾不闭合。**修复前/后这两组数完全相同**（j 与 pos 逐位相同）⇒ 用户说的"两个…开合都不对" ✔

> **管线内无解**：stage0 是零优化的 MANO 原样回放，MANO 不闭手，夹爪自然不闭手。
> 真正"闭手"发生在 Stage1（CEM 搜 grasp 闭合量）。要修只能换重建数据 / 重跑 HaWoR。

### 10.2 "开合方向"偏 —— 是"水平化约束"的固有代价（不是 bug）

把 MANO 拇指尖→食指尖向量（**真实捏合轴**）投到夹爪开合轴 Y 上：

| 版本 | `cos(Y, 捏合轴)` | 说明 |
|---|---|---|
| 未水平化的 raw SVD 姿态 | **0.819**（夹角 34.9°） | 最忠实 |
| 旧链路 `dp0v` | **−0.228**（夹角 103.2°） | 方向**反**（两指左右对调） |
| 本报告 §1–§9 的中间版 | **+0.228**（夹角 76.8°） | 方向对，但夹角被水平化扭大 |

**关键洞察**：一旦同时施加"Y 必须水平" + "Y ⊥ X(approach)"，**Y 就只剩 ±(ĝ×X) 两个选择**，
MANO 的开合方向信息被**完全丢弃**；而这 ± 号原本由 `atan2(-Y·g, Z·g)` 的象限决定（与 MANO 无关）。

⇒ "左右夹"与"跟随 MANO 的开合方向"在 MANO 捏合轴非水平时**本质冲突**（本数据捏合轴竖直分量 0.57）。
当前选择：**保留"左右夹"**（`|Y·g| = 0.000`），接受 77° 的方向偏差。

### 10.3 ★ "抖" —— 开合轴**符号**取错，夹爪本体全场刮蹭（已修）

现象量化（手指关节 `qpos[6]`，命令恒在 0.0221–0.0258）：

| 版本 | 抖动帧 `|Δ|>0.005` | 分布 | `Z·up` | `glb_4` 位移 | `glb_5` 位移 |
|---|---|---|---|---|---|---|
| 旧链路 `dp0v` | 8 | F7–F17 | +0.668 | 60.6 cm | 2.1 cm |
| 中间版 `dp2v`（符号=MANO） | **64** | **全序列** | **−0.932** | 150.7 cm | **485.9 cm** ❌ |
| `_GRIP_Y_SIGN=legacy` | 4 | F0–F20 | +0.924 | 7.1 cm | 2.4 cm |
| **最终 `fix1v`（符号=auto）** | **0** | — | **+0.932** | **0.9 cm** ✅ | **2.1 cm** ✅ |

**根因**：分支 DP 只保证 `X`（approach）与 `Y`（开合轴水平），**`Z`（夹爪"手背"）的朝向还剩一个 ± 自由度**。
而 R1 夹爪本体在 **Z 负侧** ⇒ `Z` 朝下时本体压向桌面/被撞飞的物体，全程刮蹭 ⇒ 手指被反复顶到满行程
(0.075) 又弹回 = 肉眼"一抖一抖"，并让物体被越推越远（`glb_5` 飞 4.9 m）。

我在 §4 里加的"把 Y 符号钉到 MANO 捏合轴"恰好选到了 **Z 朝下**那一侧 ⇒ 引入了这个抖动。

**修法**（`grasp_hawor._apply_branch_dp` 第 ④ 步，`_GRIP_Y_SIGN=auto` 默认）：
```
auto  = 夹爪手背 (Z) 朝上     ← |Z·up|>0.15 时用这个物理判据 (R1 本体不刮蹭)
        否则回退"与 MANO 捏合轴同向" (|Z·up| 小时判据退化)
mano / legacy / keep = 供 A/B 对照
```
整段统一翻（`R → R@diag(1,-1,-1)`，绕 X 转 180°），**不是逐帧翻** ⇒ 不引入新台阶；
`X`(approach) 与 `|Y·g|` 都不变。

> 旁证：历史已验证成功运行 `output/final_ok` 同族配置也是 `Z·up = +0.668`（正侧）。

### 10.4 顺带修掉的诊断 bug

`grasp_hawor._check_mano_R_continuity` 里取的是 `R[:, 0, 2]`（**Z 轴的 x 分量**，无意义量），
导致日志一直打印错误的 "X 朝下占比"（真实 86.7%，它打 13% —— 恰好互补所以一直没被发现）。
已改为 `R[:, 2, 0]`（X 轴世界 z 分量），并补充输出 `|Y·g|` 与 `Z·up`。
