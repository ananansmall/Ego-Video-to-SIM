## 0. 推荐结论与边界

我认为最值得优先实现、最有希望收敛的组合是：

> **保留原尺度与 CoACD 桌面场景 → 质量/惯量/材质自洽 → 小步长、低反弹、有限驱动力 → 就位后低速建立接触、有限预紧 → 保存并验证实际闭合序列 → 旧 anchor 附近小范围优化 → 按真实接触、相对持稳、任务完成分级 → 同一执行器重放 Stage2/3。**

组合依据是执行、测量、评价必须一致。初版指出的材质、相位跳变、时长耦合已有修复进展；本次新增的表面距离、接触分类、接口探测与 recipe 接线问题见第 11 节，不能照抄初版清单继续改。

“成功率最高”在这里是工程优先级判断，不是统计结论。没有数据支持 90% 等数字，也不能保证某个固定姿态必定有解。本方案给出唯一推荐基线、修改顺序、失败出口及可执行的评分定义，避免继续同时扫描大量参数。

遵守 [阶段边界文档](../2026-09-23-Stage边界定义与当前测试效果.md)：

| 阶段 | 本方案职责 | 不允许混入的行为 |
|---|---|---|
| Stage0 | 场景与物理配置校验、参考轨迹预处理 | 不通过改物体尺度/质量来自动寻求任务成功 |
| Stage1 | 局部选择 anchor；就位、闭合、稳定、执行竖直提升 20 cm 命令；按现有门冻结终验 | 不把水平搬运纳入正式 Stage1；3 cm 验收通过与完整跟随 20 cm 命令分别报告 |
| Stage2 | 接近原 anchor、复用闭合动作、复现参考携带轨迹 | 不插入额外抬升/原地保持，不修改已验证 anchor |
| Stage3 | 同一次运行延长轨迹并按策略自然释放 | 不重置抓取、不另换驱动器、不省略前缀验收 |

Stage1 完成竖直验证不保证任意后续运动可行。若参考轨迹要求物体穿桌、超出抓取可承受运动，必须报告任务约束冲突；不能靠放宽门或偷偷增加 Stage2 抬升伪造复现。

## 2. 物理模型设计：冻结一套可解释的基线

以下数值是**待验证的工程起点，不是已经调优的最佳参数，也不是实物标定值**。一次写成有版本的 profile，随后整个 Stage1/2/3 固定使用。先完成实现和读回校验，再搜索抓取，不把这些参数一起交给 CEM。

复审补充：下一轮不是把整张表重新调一遍。先冻结当前读回的质量、惯量、摩擦、阻尼、PD，修复第 11 节测量问题；offset/solver 接线作为一个单独的 profile 变更留档。未经实测，不为满足本表而同时改质量与驱动力。30 N/2 N·m 尚是待验证建议，不是当前已生效或已证明足够的值。

### 2.1 推荐基线 P1

| 项目 | P1 推荐值/做法 | 理由与限制 |
|---|---|---|
| 目标/尺度 | `glb_4`、scale=0.5，保持任务原尺度 | 不以放大物体增加成功率 |
| 碰撞 | 保留同一份 CoACD 64 凸包缓存；桌面与夹爪碰撞开启 | 检查运行 shape 数量与缓存身份，不只看环境变量；不把凸包数量再当优化变量 |
| 质量 | 优先实测；暂无实测时恢复原密度 1000 kg/m³ 的基线，目标约 0.099 kg | 该数来自当前几何体积近似，不等于真实质量；约 0.197 kg 的加重实验不是已证明更好 |
| 惯量/质心 | 与同一几何、质量分布一致；保存主惯量与质心坐标系 | 质量变 k 倍，同形状均匀分布的惯量也变 k 倍；不能仅检查正值就认定分布正确 |
| 夹爪/目标摩擦 | 两者 static/dynamic 均先设 2.0 | 使用已有历史量级，停止从 2→4→更高地补救；这是偏高的仿真假设，后续须报告摩擦敏感性 |
| 桌面摩擦 | static/dynamic=1.0 | 显式写入所有实际承载表面；防止 GLB 桌面和额外地面代表了重叠的承载面 |
| 恢复系数 | 夹爪、目标、承载面均 0 | 先做非弹性接触诊断基线；只对 material 设置并读回；不是保证不弹飞 |
| 目标阻尼 | linear=0.5 s⁻¹、angular=1.0 s⁻¹ | 保留现有平移阻尼，移除 angular=50 这种强消旋补偿；1.0 是起点，不代表真实物体阻尼 |
| 手指 PD | K=1000 N/m、D=200 N·s/m，全阶段不变 | 暂不另换已使用的驱动模型；用连续目标与有限预紧控制接触 |
| 手指力上限 | 每个驱动 10 N，全阶段不变 | 作为保护上限，不当作期望夹持力；已有 10 N 失败不能证明此值最优或无效 |
| 基座 PD | 第一版保留当前 K=50000、D=600 的实现值，记录每个自由度的单位 | 不把高刚度当作运动学锁定；平移/旋转量纲不同，不能把这个数解释成统一物理弹簧 |
| 基座力/力矩上限 | 显式起点：平移 30 N、旋转 2 N·m，随后固定 | 当前设置未显式传上限；须读回确认驱动类型。若无碰撞时都跟不上，先查单自由度跟踪，不通过无限增力掩盖 |

质量/惯量的实现原则：优先可信 mesh 的实体质量属性；若网格不封闭，不把体积数当真。可保留并明确标注现有引擎惯量近似，再按目标质量归一；不能对重叠 CoACD 凸包直接求和后宣称等于真实物体。校验主惯量有限、为正及量级，并记录 COM 是否位于合理范围。

质量、惯量、质心共同决定刚体响应；材质摩擦/恢复系数还涉及接触双方组合，并非代码注释中的通用 `min(μ1,μ2)` 规则。[PhysX 刚体动力学文档](https://nvidia-omniverse.github.io/PhysX/physx/5.1.3/docs/RigidBodyDynamics.html)

### 2.2 不允许用物理参数作弊

- 不把物体改为 kinematic，不关闭重力，不在接触中 set_pose/set_qpos 锁住物体或手指。
- 不把质量、摩擦、阻尼作为候选抓取的优化变量。
- 不降低桌面接触可见性，不用固定关节将物体粘到夹爪。
- 不以手指力上限/物重的倍数证明“必然弹飞”或“必然夹住”。驱动力上限、实际双侧法向力、物体净冲量是不同量。
- 任何 P1 模型变更都使旧物理指纹失效；旧 anchor 可作搜索初值，旧 PASS 不继承。

## 3. 仿真执行设计：控制接触分辨率与状态一致性

### 3.1 固定时间配置

推荐：physics=480 Hz、control=30 Hz、decimation=16；CPU TGS；位置迭代 16、速度迭代 1。采用当前安装接口显式设置并读回，不能仅打印配置。所有阶段同步改，不能只细化 Stage1。

相较旧配置 240/30/8，该方案提高近接触分辨率，代价是计算量增加；不承诺一定稳定。最新 p2b 已记录 480/30/16，p2a 仍是 240/30/8，不能混作相同配置的重复实验。后续可在同一冻结控制轨迹上以 960 Hz/32 做数值收敛复核，不能把高频仿真单独用作成功成绩。

每个控制区间对基座平移、旋转和 q 做统一的子步插值；旋转用连续 SO(3) 插值。插值改变了实际动作，因此必须计入执行器版本，并在所有阶段一致使用。

### 3.2 接触参数

- P1 相关 shapes 的 `contact_offset=1 mm`、`rest_offset=0`，包括目标、夹爪、真实承载面。
- contact_offset 是提前生成接触的距离，不是允许穿透深度；接触对存在也不等于已经承载。
- 这个起点配合近接触速度限制使用。先验证简单形体缓慢接触的稳定性，出现抖动/漏碰时查实际参数、几何和相对步进距离，不直接继续减小 offset。
- 首轮不同时打开未经验证的 CCD 或人为限速物体；正常运行不得把观测到的物体速度强行截断来掩盖弹飞。

PhysX 对 contact/rest offset 的说明强调它们影响接触生成距离与稳定性，过大的 offset 也会带来行为问题；数值需要结合 timestep，而不是固定越小越好。[碰撞检测文档](https://nvidia-omniverse.github.io/PhysX/physx/5.1.1/docs/AdvancedCollisionDetection.html)

### 3.3 唯一 reset 和唯一执行器

执行顺序固定为：加载 P1 → 物体无夹爪干扰地落稳 → 保存规范状态 → 从该状态生成规划几何 → reset 到该状态 → 执行动作。

规范状态至少包含：所有受影响物体 T/v/ω，robot q/qdot，全部 drive target/gain/limit，碰撞过滤，重力和 dt。还需清空控制器状态、接触统计、上一轮 latch 与缓存引用。冷启动独立场景复验可检查求解器历史状态影响。

Stage1 可以在开放夹爪、无交叠条件下初始化到 anchor；Stage2 则按参考接近。二者到闭合起点时必须满足同一就位条件：建议位置误差≤1 mm、姿态≤1°、线速度≤5 mm/s、角速度≤3°/s，连续 5 个控制点。最大等待时间 1 s；未到位返回 `NOT_READY`，不是按固定帧数强行闭合。

这些是本方案的入口条件，不是放宽旧门。若参考轨迹不允许就位减速，需明确任务冲突；不能同时要求“高速不停顿”与“固定构型静止闭合”。

## 4. 闭合与时序：推荐“接触感知生成、完整冻结验证”

### 4.1 为什么第一版选这个组合

在线力控可以有价值，但目前分项力与跨阶段执行尚不可靠，直接再加一个闭环会扩大问题。推荐第一版：**用接触信息生成有限预紧的闭合轨迹，随后冻结整个序列，独立复位重复验证；Stage2/3 执行同一个序列。**

这兼顾了“别无界挤压”和已有“验证动作=交付动作”的要求。探索时的闭合不计为最终验证；冻结序列没有通过，就不能交付。如果以后改成在线反馈控制，必须版本化同一个控制策略并贯穿三阶段，不能与这一版混用。

### 4.2 具体控制规则

仍使用一个公共开合标量 q，避免为了仿真成功偷偷赋予真实平行夹爪没有的独立手指控制能力。

1. **开口**：先用已有候选 recipe 的 q_open；P1 新基线可从 0.03 m 开始，必须通过真实几何的开放夹爪包络检查。不能仅凭 `gap0+2q` 判定所有截面都能包住；不满足时明确生成新 recipe。
2. **自由闭合**：公共 q 目标速度≤20 mm/s，加速度≤0.1 m/s²。
3. **进入接触附近**：真实最小表面间隙<3 mm，或任一指有可信目标接触后，q 速度≤5 mm/s。只改变目标推进速度，不切换 PD 增益。
4. **单侧接触**：允许继续缓慢闭合，但相对首次接触的公共目标额外推进最多 2 mm；仍无法建立双侧接触则返回 `UNILATERAL_GRASP`，交给位置修正，不继续深压。
5. **双侧接触**：连续 3 个控制点确认两指均对目标承载后，记录 q_touch，目标有限推进 0.5 mm 作为初始预紧，速度≤2 mm/s；探索上限为 1.5 mm，超过就判当前构型不足，不自动加力。
6. **保持**：0.5 s；持续滑移、桌面挡停、物体被推离初始构型，则失败。最大闭合耗时 4 s，超时失败；不能为了结束时间线而直接跳到 q_final。
7. 将实际生成的完整 `q[t]`、时标与状态边界冻结，**CLOSE/SETTLE/提升之间最后一个 q 连续**，重复验证不重新计算目标。

K=1000 N/m 下 0.5–1.5 mm 的稳态误差对应约 0.5–1.5 N 的驱动弹性项，仅用于量级检查；它不等于总接触法向力，也不保证抗转动力矩足够。理想平行侧夹的 `2μN≥mg` 只能做最低量级参考，真实斜面、偏心和转动仍须物理验证。

### 4.3 Stage1 提升与稳定窗口

阶段长度独立相加：就位等待 + 生成/冻结闭合时长 + 0.5 s 稳定 + **4 s 平滑竖直提升 0.20 m** + 0.5 s 提升后保持。提升采用五次平滑曲线，起止速度与加速度为零。

原先 `n_frames=160` 不再支配整个动作长度；增加 close 时间不得提高提升速度。保持是 Stage1 的抓取验证窗口，不进入 Stage2 参考轨迹。

本次复审撤回初版将“最终净提升≥18 cm”作为推荐交付硬门的安排，保留用户指定的现有成功定义：提升≥3 cm、两指同时挡停的抬升帧比例≥50%、目标最终脱离桌面支撑、xy 漂移≤20 mm，以及现有数据有效性和物理可行性检查。搜索与终验必须使用同一份 criteria，而不是各自取环境变量默认值。

完整跟随 20 cm 命令、末端保持和真实双侧接触是必须如实报告的诊断，不能把“命令 20 cm”当作“实际提升 20 cm”。其中真实双侧接触观测尚需补齐；旧挡停率不是其真值。若要用这些诊断升级正式门，需单独确认并版本化，不把旧 3 cm PASS 改名为失败或悄悄换成 18 cm 门。

Stage2 按 recipe 复用闭合及原有抓取稳定段，随后进入原参考轨迹；不搬入 Stage1 的 20 cm 提升或顶部保持。

## 5. 先定义观测，再定义奖励

### 5.1 接触量

每个物理子步记录目标精确 body ID 与 finger ID。将冲量分解为法向/切向，法向力估计为法向冲量除以 physics dt。一个控制周期的均值应为整个周期累计冲量除以 control dt，不能重复除 dt 或将每子步力直接当作总力累加。

当前 `physics_env.get_grasp_force_detail()` 分开了对象，但仍是冲量模长之和，**不是法向力分解**；不应直接作为精准力反馈输入。

建议双侧承载判据：每指对目标的周期平均法向力大于 `max(0.05 N, 0.02mg)`，连续 3 个控制点；阈值需由无接触噪声与已知接触样本验证。它仅用于识别有效接触，不等于充分夹持力。

同时单独记录目标—桌面、夹爪—桌面、掌部—目标接触。不能用总接触数、挡停率或触到任何动态物体代替上述分类。

### 5.2 持稳量

令 `C(t)=inverse(T_W_G(t)) @ T_W_O(t)`。C0 取闭合稳定段最后 0.2 s 的有效参考状态，整个携带阶段固定，不随滑移重新更新。

- `e_p(t)`：C 相对 C0 的平移变化。
- `e_R(t)`：C 相对 C0 的旋转测地角。
- `v_rel(t)`：物体质心速度减去夹爪刚体运动在该质心位置的速度，包含 `ω_G × (p_O-p_G)` 项。
- `drop_duration`：抬离支撑后双侧目标承载丢失的连续时长。
- `task_progress`：沿阶段目标轨迹的实际进度；不能只看路径长度或位移模长。

Stage1/2/3 可统一记录 5 mm / 5° 尺度的持稳诊断。Stage2 保留已有 5 mm / 5° 与实际搬运进度门；Stage1 不未经批准新增该门或把 50% 挡停率换成 90% 双侧承载率。初版建议的双侧承载≥0.90、连续丢失≤0.10 s 目前只作诊断，不能与旧成功率混报。

### 5.3 分清两类失败

- **没有夹住**：单侧/无接触、桌面支撑未解除、物体没有跟随。不是所有这些情况都说明仿真不稳定。
- **异常碰飞**：接触后大幅偏离预期运动，并产生异常相对速度/转动。优先排查初始化交叠、命令跳变、恢复系数、惯量和基座碰撞，而不是首先提高夹持奖励。

本低速基线的建议 early-abort 上限：接触后 `|v_rel|>0.5 m/s` 或相对角速度>10 rad/s 持续两个子步；或物体离开允许运动包络 0.10 m。非有限状态立即终止。阈值只用于防止异常轨迹继续积分，不能代替更严格的任务成功门，也不能拿终止前的最大高度计成功。

明显夹爪—桌面穿透建议以 0.5 mm 持续 3 子步作为初始失败阈值；单步更深冲击也须保留峰值，不能被时间平均隐藏。桌面承载阻碍闭合即失败，即使 separation 恰好为零。求解器容差与渲染网格不能互相代替。

## 6. 奖励设计：唯一 evaluator、分级排序、连续失败代价

### 6.1 返回结构

```text
evaluate_rollout(trace, task, criteria) -> {
  data_valid, physics_valid, task_success,
  failure_reason, progress_tier,
  costs: {gap, push, clearance, relative_pose, progress, lost_contact, deviation, smooth},
  metrics, criteria_revision
}
```

先处理缺测、弹飞与明显穿透；这些是不可交付结果，后续分数不得覆盖。关闭旧的分散 reward 实现，只保留兼容日志，不再同时运行“旧求和→硬扣分→新分级覆盖”三套体系。

### 6.2 排序等级

| 等级 | 条件 | 同级内优化内容 |
|---|---|---|
| invalid | 数据无效、初始化错误、异常弹飞、明显穿透 | 不参与正常可行 elite；按失败标签统计，不能作为成功 seed |
| 0 | 物理状态可解释，但未建立稳定双侧目标接触 | 两侧接触面距离、目标被推动量、几何违反量 |
| 1 | 已建立稳定双侧接触，但没有完成提升/保持任务 | 相对位姿、接触丢失、任务进度缺口 |
| 2 | 完整阶段任务与持稳门均通过 | 更小相对误差、更小局部修正、更平滑命令 |

无接触候选不交付，但可以保留连续失败代价用于找到接触；把它们全部设成同一个 -500 会丢失改进方向。若所有候选都因物理无效被剔除，则停止该轮并报告具体约束，不用无效状态强行更新分布。

推荐直接按 `(task_success, progress_tier, -J)` 比较，不用大常数假装严格分级。若接口强制需要标量，可对非负有限 J 使用 `R=10*tier-J/(1+J)`，确保等级不被无界子代价跨越；无效结果另存 mask，不让 NaN 进入排序。

### 6.3 具体代价与起始权重

统一米、秒、弧度，按以下物理尺度归一；时间聚合用积分/持续时间或均值，不直接按帧数求和，避免“多保持几帧改变总分”。

```text
ρ(x) = x²                  (|x|≤1)
       2|x|-1              (|x|>1)

J_gap = mean_end_close[ρ(max(d_left,0)/1mm) + ρ(max(d_right,0)/1mm)]
J_push = max_pre_lift ρ(object_displacement_from_settled_pose/2mm)
J_clear = mean + max of ρ(max(required_margin - signed_gap,0)/0.5mm)

E(t) = ρ(e_p(t)/5mm) + ρ(e_R(t)/5deg)
J_rel = mean_carry E(t) + max_carry E(t)
J_progress = ρ(max(required_progress-actual_progress,0)/progress_scale)
J_lost = missing_bilateral_duration/carry_duration
         + ρ(longest_missing_duration/0.10s)
J_dev = ||delta_anchor_position/5mm||² + ||delta_anchor_rotation/2deg||²
J_smooth = time_mean of normalized command acceleration²

tier 0: J = J_gap + J_push + J_clear + 0.05 J_dev
tier 1: J = 2 J_rel + J_progress + J_lost + 0.05 J_dev
tier 2: J = J_rel + 0.05 J_dev + 0.05 J_smooth
```

权重是清晰的第一版设计，不是已经学出的最优值；先验证固定样本排序，再允许后续有记录地调整。`progress_scale`：Stage1 用 0.20 m；Stage2/3 用各段规定的参考进度并做零运动分支处理，禁止除零。

`d_left/right` 必须是对应指腹与目标表面的间隙，不能用顶点最近距离、物心距离或“两侧差值”冒充。几何算不可靠时返回 unavailable，不能设零。CoACD 重叠内部面不作为期望指腹接触面；候选接触点应尽可能对应外表面，并由引擎实际接触确认。

安全余量按相位使用：接近阶段正余量；闭合阶段允许目标接触，避免真穿透；桌面/非目标障碍始终禁止真正的承载阻挡。**终端闭合的桌面 `required_margin` 建议为 0，不把 +1 mm 或 +3 mm 隐式变成成功硬门。** 0～1 mm 贴桌候选可以保留，但负间隙不能改名为零，持续桌面接触也不能未经运动/受力分析就改名为挡停。接近阶段正余量是路径偏好，不能掩盖末端必然趋近零净空；详见第 11 节。

### 6.4 必须删除/降级的旧奖励

- 不再奖励峰值力、最大抬升高度、手指行程对称和“看起来朝下”。
- 不再用“接触次数>25 且提升不足 5 cm”统一扣 60 分；由 push/slip/progress 说明失败。
- 不将世界 xy 漂移作为 Stage2 水平携带的主要失败量；那本来就是任务运动。
- 不在新等级最后覆盖弹飞/穿透状态。评分异常必须显式失效，不保留旧分。
- `_assess_grasp`、Top-K、CEM elite、重复确认与终验都消费同一 evaluator 和 criteria revision。

## 7. 搜索设计：只优化能解释的小修正

### 7.1 Stage1

第一轮固定参考帧、姿态和 P1，仅优化旧候选附近三维平移，信赖域半径 5 mm。先零偏移及各轴 ±1/±3/±5 mm 小集合，再对好的区域做局部细化；避免每轮同时改变多帧参考、角度、闭合量和物理参数。

同一候选的闭合由第 4 节生成，再冻结重复验证。若平移域内均无可行双侧构型，第二轮才开放相对原参考姿态≤2° 的微调，仍受已有 MANO 硬约束约束。2° 不是额外放宽总姿态容差。

预紧不是自由无限搜索变量：先固定 0.5 mm，只有已确认双侧接触、无桌面问题而持稳不足时，才在同一候选上比较 1.0/1.5 mm，全部受相同力与命令速率上限约束。

最近侧很近或两指位置对称，不足以证明抓取可行；若所有小修正都失败，报告真实接触构型和约束冲突，不宣称“奖励再调一下必能成”。

### 7.2 Stage2/3

Stage2 anchor 固定，只对接近段搜索 `δp(u)=R_anchor a·64u³(1-u)³`，`||a||≤5 mm`。偏移及其前两阶导数在两端为零；参考轨迹本身的就位速度约束仍单独处理。

携带不再加临时 preload、抬升或保持。Stage2/3 使用同一时间参数化，并在接续处检查位姿、线/角速度和 q 连续。初始可保留 Stage2 当前 2× 时间尺度，Stage3 接续必须匹配末端实际时标，而不是各自选一个倍数。

保留当前 `svd_palm` 与分支 DP，不在这一轮更换整套重定向。明确参考点是 gripper base 还是抓取中心；若需要修正抓取中心，应统一用 `p_TCP=p_base+Rr` 计算后反解基座，不能独立改 R 后默认 TCP 不动。是否改变参考点定义需另一个明确版本，不与 P1 物理修复混杂。

Stage3 默认合并路径继续保留，但必须复用共享执行器和相位 evaluator：前缀按 Stage2 相位核验，后缀携带不含释放，释放允许自然掉落；`enable_release=False` 必须真正不释放。

### 11.1 结论与三项决策

### 11.3 贴桌允许什么，禁止什么：不要直接删除失败门

物体在 CLOSE/SETTLE 由桌面支撑是正常初始条件。夹爪贴近桌面也不自动意味着作弊。需要区分：

| 情形 | 建议处理 |
|---|---|
| 有接触记录、法向冲量近零、无穿透 | `PRE_CONTACT`，不能仅按 contact count 宣称支撑或卡住 |
| 夹爪轻触桌面，仍能按命令运动，目标接触可辨识 | `TABLE_TOUCH`，保留候选和接触代价，不自动宣称抓取成功 |
| 夹爪持续桌面受力，沿命令方向明显跟踪失败或闭合停滞 | `CONTACT_CONSTRAINED`；结合接触方向区分桌面阻挡，证据不足则 `UNKNOWN`，不得放行为成功 |
| 明显穿透、目标被掌部铲起、另一指由桌面代替承载 | 不可作为真正双侧夹持交付 |
| 提升后目标不再由桌面支撑、真实双侧目标接触仍在、运动稳定 | 才进入抓取成功核验；不能用上述几何/接触标签替代其余门 |

“桌面阻挡”至少联合判断：桌面接触法向冲量及方向、命令与实际 q/T 的残差、实际速度、持续时长。目标本身也会挡停手指；同时存在目标与桌面接触时，不能仅凭残差就把因果全归给桌面，必要时保持未决标签。

实现上保留 `legacy_result` 和新的 `diagnostic_result`，记录 `criteria_revision`。**不直接跳过 `load_bearing_block` 硬门**，而是先修其上游分类证据，用明确反例校验；新旧分歧逐条报告后再统一启用新分类。当前 `gnd≥0` 门不偷偷改成负数容差，-0.3 mm 也不能写成“约等于 0”。如引擎误差确需容差，先用已知形体标定、明确版本及授权，再使用。

目标支撑也要按相位：闭合时受桌面支撑并非失败；提升初期可以从支撑转为脱离；验收应确认**提升末段及最终状态**脱离，而不是用整个提升区间接触占比代替最终支撑。当前 Stage1 在 lift 起点重置后累计统计，仍需区分整段历史与末端窗口。建议另报末段 0.2～0.5 s（具体固定为配置）法向冲量、接触间隙和有效采样数，不能靠稀释历史接触比例通过，缺测仍 UNKNOWN。

所有桌面/承载面采用精确 body ID 映射，包含真正的 GLB 桌面；当前探针中的 `"ground" in name` 不足以证明“桌面碰撞都可见”。“对象有 contact 记录”和“对象由桌面承载”也要分开，不能只修计数、不修物理语义。

### 11.4 几何扫描怎么做：回答有限的问题，不制造另一种假结论

**输入必须来自同一规范落稳状态和实际 physics shapes**：shape 顶点/尺度/局部 pose、link/actor world pose、所有 CoACD 凸包、完整两指/掌部和真实桌面。保存几何 hash 与变换。不得改用渲染网格近似后称“真实碰撞几何扫描”。

距离使用凸体 GJK 距离及相交检测；穿透深度可用 EPA 或经过验证的对应方法。也可用正确的三角面/边最近特征查询。OBB/SAT 可做粗筛，顶点最近距离不能充当最终表面距离。CoACD 需要按所有相关凸包组合处理，区分并集外表面和内部重叠面。

扫描顺序：

1. 以旧 anchor 为中心，先固定姿态，平移域不超原方案 ±5 mm；例如 1 mm 粗步长，对候选区做 0.25～0.5 mm 细化。明确这是采样精度，不是连续空间完备证明。
2. 同时扫描 URDF 允许的公共 q，仍是一维开合；若无候选，再在原 MANO/任务限制内做姿态微调。不能从固定姿态无解跳到整任务无解。
3. 对净空 0/0.5/1/2/3 mm 分别报告 `max(d_left,d_right)` 的最好值及对应姿态；这些是对照切片，不是五档成功门。输出两侧最近点、法向、交叠信息和碰撞部位。
4. 不只检查终点：检查开放夹爪能否就位、单调闭合的扫掠路径、初段抬升能否离桌。离散路径采样须按最大运动量自适应细化或采用连续碰撞检测，不能只看少数关键帧就宣布路径无碰撞。
5. 输出最好的少量候选及可复查几何，随后用原桌面碰撞开启的动力学场景验证。几何双侧触碰不保证力闭合、抗转稳定或可搬运。

结论只能使用以下三种之一：

- `FOUND_GEOMETRIC_CANDIDATE`：指定域内找到几何/路径候选，动力学未确认。
- `NO_CANDIDATE_IN_SAMPLED_DOMAIN`：指定范围和采样分辨率没有找到；不是不存在证明。
- `PROVEN_INFEASIBLE_IN_SPECIFIED_DOMAIN`：只有具备连续域保守界或其他严格证据时才能使用，且不外推到未检查的姿态/路径。

不承诺“几分钟扫描即可证明任务无解”。几何预处理、凸包组合、姿态域和路径检查决定成本。禁止桌面碰撞的对照改变了动力学及可行域，只能说明结果对桌面敏感；不能证明原场景可行，更不能排除奖励问题。若要做因果对照，应固定同一初态、同一命令和配置，其结果仅作诊断，不能计入正式成功率。
