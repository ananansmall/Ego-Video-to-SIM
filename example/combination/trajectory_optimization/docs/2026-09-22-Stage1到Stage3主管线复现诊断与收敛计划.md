# Stage1 → Stage2 → Stage3：当前能否复现，以及如何停止无效试错

日期：2026-09-22。性质：代码审查、已有产物核对、只读小测试；本轮没有修改运行代码，没有重跑完整抓取管线。

关联历史：[Stage1-CoACD 桌面碰撞实验记录](2026-09-20-Stage1-CoACD桌面碰撞-奖励与参数实验记录.md)。本文按当前执行路径判断，不把历史注释里的“根因”“已修”“必然成功”当作证明。

## 1. 先回答方向问题

**阶段划分可以保留，但“Stage1 抬起成功，Stage2 到同一位置就必然抓住，Stage3 复制后续轨迹就必然成功”不成立。当前代码也还没有实现足够严格的跨阶段等价重放。**

这里缺了两项前提：

1. Stage1 成功必须是可重放的“初始状态 + 完整闭合动作 + 稳定接触状态”，不只是一个位姿和一次 lift PASS。Stage2 接近过程中可能改变物体状态；同一个夹爪目标位姿不保证同一个相对接触构型。
2. 单方向竖直提升验证的抓取，不自动具备后续平移、转动所需的持稳能力。命令轨迹连续也不等于物体轨迹连续跟随。

所以不是先推翻整个框架、换物体或换优化器，而是补上上述前提，并验证执行一致性。现有证据既不足以承诺最终成功，也不足以宣布这个物体和夹爪组合不可能完成任务。

“轨迹复现”需要分开说：夹爪命令沿参考轨迹运动；实际夹爪跟踪命令；物体在释放前保持相对夹爪位姿。这三件事目前不能用同一个 PASS 替代。

## 4. 仍需要处理的具体代码问题

### 4.1 P0：同一 bundle 不等于同一实际执行动作

`stage2_reconstruct_mixin.py:3250` 从 bundle 取出 q 后，还应用 `_GRIP_PRELOAD` 和闭合下限。`local1` 与 `pl2` 的日志给出相同 bundle 短 hash `c2c93cac7250`，但 pl2 执行了额外 2 mm 预载。

Stage3 默认合并执行器则在 `stage3_optimize_mixin.py:701` 附近直接执行 `bq[i]`，没有复用 Stage2 的这套命令后处理。

因此，现在的“保存命令”“Stage2 实际验证命令”“Stage3 重放命令”可能不是同一动作。这是确定的调用契约缺口；它不能解释所有默认零预载运行，但足以破坏开了这些实验参数时的跨阶段复现。

建议：所有改变命令的参数在生成最终执行时间线前生效，或纳入同一个共享执行器和完整配置身份；保存逐控制点实际下发命令，而不是只保存修改前数组。重放时禁止再隐式加减一次。

### 4.2 P0：Stage3 默认路径绕开了 Stage2 重放验收

`stage3_optimize_mixin.py:823` 默认 `_S3_COMBINED=1`，进入独立的 `_rollout_s2plus3_combined()`，并不是下面那个“精确重放 Stage2，再条件接续”的实现。

具体差异：

- 合并执行器有自己的一套 reset + 5 次 warmup；Stage2 另有初态设置和物体静置流程。拼接数组不证明两套初始物理状态相同。
- `:776` 返回的 `stage2_replay.gate_result.passed` 是**直接写死的 True**，不是本次前缀物理测量得出的结论。
- 合并路径的 Stage3A 只检查相对平移不超过 10 mm 和双侧比例不低于 0.80，没有把相对旋转等正式路径判据一起接上。
- 默认分支没有传递 `enable_release`；即使调用者要求不释放，也会执行构造出的释放后缀。
- `_S3_GRIP_K_SCALE/_S3_GRIP_F_SCALE` 可以改变后缀驱动参数，但该函数没有对应的完整恢复流程；需要防止同一进程重复试验带入上次状态。

**单次连续执行的设计可以保留，不建议盲目切回旧分支。应复用一个执行循环、一个 reset、同一套前缀判据；不是再增加第三套流程。** Stage2 先前通过，只能作为进入 Stage3 的前提，不能替代合并重放这一次前缀的实际核验。

关于释放：历史文档记有“自然掉落”的任务选择，因此空中释放本身不能直接认定为 bug。当前 Stage3B 只证明张开到位，不证明精确放置；需要明确标成自然释放策略，不应无授权改成落桌放置任务。若只验证携带，应确实遵守关闭释放的参数。

### 4.3 P0：统一验收仍存在缺测被当通过的链路

两处已经确认：

1. `stage1_grasp_mixin.py:2371` 的 `bool(_og.get('supported'))` 把统计层的 `None` 转成 False，丢失“未知”和“确认无支撑”的区别。下游函数再检查 None 已来不及。
2. `:1132` 附近的数据有效性只查 None，未检查数值有限性。本轮直接调用 `_assess_grasp`，令 lift、桌面净空、挡停率、漂移为 NaN，其余字段合法，实际返回 `data_valid=True, task_success=True`。

另外，`s1_true_grasp_ratio` 在 `:2339` 附近仍由两指 `actual_q-command_q` 超阈值的比例计算。它是“双指挡停率”，不是经过接触对象、接触法向和持稳验证的成功概率。桌面或其他接触也能产生位置误差。

建议：修正数据类型与有限性检查；未知状态跨层保留。真实目标双侧接触、桌面承载、相对位姿稳定分别记录与验收，不再让一个名称替代三项物理证据。

### 4.4 P1：新增抬升与保持组合，产生确定的反向跳变

`stage2_reconstruct_mixin.py:835` 先追加 `anchor+[0,0,dz]`；`:867` 的搬运前保持段却追加原始 `anchor`；后续 carry-hold 又返回升高后的 anchor。

本轮纯时间线复现：

```text
_S2_LIFT_OFF_CONTROLS=10
_S2_LIFT_OFF_M=0.025
_S2_PRE_CARRY_HOLD_CONTROLS=3
_S2_CARRY_HOLD=1

control 60 → 61: Δz = -25.0 mm，两个点的 phase 都为 CARRY
```

该组合不是“抬起后保持”，而是“抬起—突然下降—再上去”。这些开关默认关闭，不能把它当成所有现有失败的原因；但在建议继续试这些组合之前必须修正，并补组合测试。保持应继承上一控制点，接回参考轨迹还需检查位姿、速度连续性。

### 4.5 P1：最需要逐帧比较时，Stage2 CSV 仍可能写不出来

`stage2_reconstruct_mixin.py:4170` 的 `if _s2_od and _ba` 及后续多处 `trace.get(...) or []` 对多元素 ndarray 做布尔判断。local1 现有日志确实记录了 `The truth value of an array ... is ambiguous`，然后捕获异常继续。

建议先修成显式 None/长度判断；把命令、实际状态、目标接触和失败点写入同一份可读取 trace。否则每一轮仍只能看摘要，无法查到第一处偏离。该诊断错误不是物体滑落的力学原因，但会直接妨碍定位。

### 4.6 尚未闭环：场景快照、搜索标准和局部持稳验证

- 快照检查目前在规划几何路径，默认非严格；执行 reset/静置之后尚没有把状态相等作为强制入口条件。见 `stage2_reconstruct_mixin.py:2040` 的实际分支。不能把“从快照取几何”直接写成“规划与执行初态已保证一致”。
- `_assess_grasp()` 的调用有所统一，但 Top-K 还有额外选择门；CEM elite 更新仍直接 `np.argsort(rewards)`（`stage1_grasp_mixin.py:3847`）。最终判断更严格，不意味着搜索过程自动在朝同一个成功目标更新。
- Stage1 默认 rollout 的实际运动仍是闭合、稳定、竖直抬升到结束（`:1795,1823`）；并没有因为新增了“阶段统计”就自动具备“抬升后保持 + 短水平携带”的动态验证。

## 5. 需要修正的历史推论

原实验记录 §§121–122 将“斜楔挤出”作为唯一机理，并写成“当前配置不能成功”。应降级为**候选解释**：

- 两指关节位置不对称不能单独推出单侧支点、接触法向或净扭矩；不规则物体也不要求两指行程完全相等。
- 接触双方名称说明碰到了谁，不说明两侧法向力足够、摩擦足够、且接触力矩能够抵抗后续动作。
- 几组预载/重座失败，只能否定这些已试配置，不能证明整个可行域为空。
- 有限分辨率的几何扫描可提供候选；“扫描未找到”也不是“物理上不存在”的证明。
- 注释中的“改刚度不改接触构型”“放慢一次无效就排除速度影响”等都是过强推断，不宜继续作为下轮修改的依据。

需要在开始翻转的几个物理子步保存两指与目标的接触位置、法向、冲量及物体速度，才有条件判断挤出、接触点滑移、桌面约束或命令跳变谁先发生。

## 6. 下一步：四组对照，先分因再修

先冻结一个目标物、原尺度、CoACD 配置、桌面、材质、质量、碰撞过滤、dt/decimation、驱动参数和一个已有候选。不要同时换 anchor、闭合量、reward、验收门。暂不再开整轮 CEM。

首先把保存/实际执行命令、reset、缺测判定和 trace 写出修到可对照。对照共用同一个执行器；每组从同一个规范物体初态开始。直接 anchor 初始化只用于隔离实验，不算完整任务成功。

| 实验 | 闭合前怎么到达 | 闭合后执行什么 | 要回答的问题 |
|---|---|---|---|
| A | 直接初始化在 Stage1 anchor，沿用其开口 | 冻结的原 Stage1 闭合、稳定、竖直提升 | 旧候选在当前物理设置下还可重放吗？ |
| B | 完整 Stage2 接近 | 与 A 逐点相同的闭合、稳定、竖直提升 | 接近是否破坏了本来可成功的抓取？ |
| C | 与 A 相同 | 相同闭合后，执行 Stage2 实际携带段 | Stage1 的成功是否不能迁移到该携带动作？ |
| D | 完整 Stage2 接近 | 与 C 相同的携带段 | 接近与携带组合是否可行？ |

每组先做 3 次独立复位重复用于排障；这不是对高可靠成功率的统计证明。不能挑最好的一次代表整个候选。

结论分支必须提前约定：

- **A 失败**：先处理 Stage1 复现。对比旧动作、当前动作和初态，若一致后仍不稳，再查接触几何/闭合。此时不该继续调 Stage2 接近轨迹。
- **A 成功、B 失败**：主攻 Stage2 接近与就位。比较闭合开始时物体 T、v、ω，实际夹爪 T、q、qdot；修第一次偏离，不挪 Stage1 anchor 掩盖问题。
- **A 成功、C 失败**：主攻抓取的携带稳定性。保持原候选先加诊断用的短提升、保持和小幅目标方向运动，找出失稳开始条件；再有依据地调整接触截面/方向或闭合控制，而不是无限预载。
- **B、C 成功、D 失败**：检查接近残余速度与携带启动的耦合、相位切换及时间参数。
- **D 重复成功**：冻结 Stage2 完整执行结果，才开始 Stage3 的持续携带验证。

每次比较输出“第一处分叉控制点/子步”，至少含：命令与实际夹爪位姿、两指命令/实际 q、物体 T/v/ω、两指各自目标接触、桌面接触、相对位姿平移/旋转。渲染必须来自这次物理 trace，并标明不是命令预览。

### 对 Stage1 的具体方向

保留已有候选作为对照，不等于认定它是真成功。A 稳定后，给候选加“脱桌后保持 + 短携带”的独立验证，确认目标不是仅随竖直运动被托起。

若需重搜，先在原任务尺度和 MANO 约束内，根据实际接触几何做小范围候选扫描；把可达入口也纳入检查。不要先把物体放大、改抓取方式或取消桌面碰撞。那些属于任务变更，不是代码修复。

### 对奖励和选择的具体方向

现在不建议再加一个大权重求和项。先冻结一组候选，把有效性、物理约束违反、接触持稳、任务进度和总 reward 并排输出，确认排名是否符合预期。

下一轮设计应统一：无效数据不能交付；物理不可行解不能压过可行成功解；成功解内部按跟随与平滑代价排序；全失败时保留连续的约束违反代价供搜索前进，但标明仍然失败。这个顺序要贯穿 Top-K、CEM elite、重复确认与终验，而不只是最后加一道门。

“某次 shaping 改坏了”不等于所有接触 shaping 都不能用；也不证明当前以 lift 为主的评分足够。需要固定样本的排序证据再改搜索，而不是每次改权重同时更换样本分布。

### 对 Stage3 的具体方向

先在共享执行器中只重放 Stage2 前缀，测得相同判据与状态序列；再在同一次运行追加后缀，不 reset、不临时切 PD、不改已验证闭合命令。

Stage3 的成功至少分别报告：本次前缀通过、后缀携带相对位姿稳定、目标沿轨迹移动、自然释放是否执行。平移和旋转都检查；不要把“夹爪张开”叫作精确物体轨迹复现。若将来要求稳定放置，再另设明确任务策略。
