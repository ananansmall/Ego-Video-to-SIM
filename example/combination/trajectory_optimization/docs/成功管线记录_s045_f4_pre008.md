## 4. 全流程阶段语义（成功的接线方式）

```
Stage1  6DOF CMA-ES 短仿真 → best_grasp.npz（20 close + 10 settle 的 recipe, anchor 位姿）
   ↓  recipe + scene digest 一起进 bundle, 后续阶段校验 digest 一致才允许复用
Stage2  从共享 reset 出发: MANO 自由段 → 轴向直线逼近 (d_stop) → FINAL_APPROACH → 复用 Stage1 recipe
   ↓  硬门全过才产出可执行 bundle（3 次独立 reset, 要求 3/3）
Stage3  先"原样重放 Stage2"并要求其硬门通过（防止 Stage3 建在虚假状态上）
   ↓  再接 append-only 后缀: CARRY → PRE_RELEASE_SETTLE → RELEASE → RELEASE_SETTLE → 退避
```

**关键约束**：`STAGE1_REUSE_MISMATCH` —— 任何改动**物理参数或物体 scale**（摩擦、PD K/D、scale、形状）都会改变 recipe digest，**必须连带重跑 Stage1**；只改平滑方式（`_SMOOTH_MINT`）同样会改轨迹，也要重跑。

## 5. 本轮使全管线贯通的关键机制

### 5.1 夹持预紧 `_GRIP_PRELOAD`（最重要）

**问题**：Stage1 recipe 给的手指闭合命令是 `q_grasp=0.0086`，但物体把手指挡停在 `0.0248` → 驱动器**抵达目标后不再推进**，实际夹持力只有 `K×(0.0248−0.0086) = 16.2N`，携带时容易滑。

**做法**：在**真正握持的相位**（Stage2 的 `index ≥ close_start`；Stage3 的 `CARRY` / `PRE_RELEASE_SETTLE`）把手指命令再压低 `_GRIP_PRELOAD`，使驱动器在物体挡停后**持续顶住**：

| | 手指命令 | 手指实际 | 夹持力 `K×Δ` |
|---|---|---|---|
| 无预紧 | 0.0086 | 0.0248 | 16.2 N |
| **预紧 0.008** | **0.0006** | **0.0246** | **24.0 N（+48%）** |

**必须避开的坑**：释放相位（`RELEASE` / `RELEASE_SETTLE`）与释放后相位（`POST_RELEASE_BLEND` / `MANO_FOLLOW`）**不能施加预紧**。判据要写白名单（`"CARRY" in phase or "PRE_RELEASE_SETTLE" in phase`），**不能写 `"RELEASE" not in phase`** —— 后者会漏掉 `POST_RELEASE_BLEND`/`MANO_FOLLOW`（相位名里也不含 "RELEASE"），把已全开的 `0.05` 压成 `0.042`，导致手指张不到位、Stage3B `OPEN_TRACK` 失败。

### 5.2 到 F50 的平滑到达（不要硬停）

原 `PRE_READY_LINEAR_SPEED_MPS = 10mm/s` 逼迫基座在 F50 前完全静止，与"平滑移动到抓取"直接冲突。实测该窗口基座速度 `10.71mm/s`（仅超 7%），而位置 0.18mm / 姿态 0.017° / 角速度 0.31°/s / 物体漂移 0.82mm **全部远优于容差** → 速度项已成为唯一阻塞且不反映抓取质量。**改为 30mm/s**，允许"行进中抓取"。

配套：`preclose` 手指跟踪误差只评估**就位窗口**（`close_start` 前 5 个控制点），不把接近段被物体轻擦顶开的瞬时值算进来。

### 5.4 ★ CoACD 默认开启会让全流程 0/3 失败（2026-09-12 实测）

`grasp_hawor.py` 里：

```python
self.coacd_target = os.environ.get("_COACD_TARGET", "glb_4")   # 默认只分解被抓取物体 glb_4
```

而 `data_loader.load_glb_with_physics` 的碰撞体分支是：

```python
if _is_coacd:            # ← CoACD 多凸包
    ...
elif body_type == "dynamic":
    _shape = os.environ.get('_OBJ_SHAPE', 'box')   # ← _OBJ_SHAPE 只在这里生效
```

**即：只要 CoACD 生效，`_OBJ_SHAPE=box` 会被整个跳过**（因为它是 `elif`）。

**实测后果**（`_OBJ_SCALE=0.45` 下的 `toy_0`）：

| | CoACD 开（默认） | CoACD 关（`none`） |
|---|---|---|
| 日志 | `CoACD 凸分解 = 121 个凸包` | 无 CoACD 日志 |
| 耗时 | **202 秒** | 0 |
| 碰撞体数 | `target=120` | **`target=1`**（box） |
| SAPIEN | `QuickHullConvexHullLib::findSimplex: Simplex input points appers to be almost at the same place`（凸包退化） | 无 |
| warmup | 物体**自转 29.09°**、位移 8.63mm | 稳定 |
| 结果 | **`RESET_DRIFT` → Stage2 0/3 → 全流程不运行** | **3/3 PASS** |

**原因**：`toy_0` 被缩到 0.45 后网格很小，CoACD 切出 121 块退化凸包碎片；碎片之间互相穿透、被地面弹开 → 物体在 warmup 自行翻滚。

**结论**：当前配置下必须 `_COACD_TARGET=none`。若将来要用 CoACD 的精确接触判定，需要先解决退化问题（提高分辨率 / 限 `max_hull` / 或在未缩放的原始尺度上分解后再缩放）。
