## 3. Stage 1：抓取姿态优化

### 3.1 目标与产出

- **目标**：给出一个**物理上抓得住**的 anchor 位姿 `(pos, R)`，以及 `q_grasp`（闭合目标开度）与
  `close_controls / settle_controls`（闭合与静置的控制点数）。
- **产出**：`stage1/best_grasp.npz`、`stage1/stage1_grasp_recipe.json`（含 `scene_digest`）。

### 3.2 五层搜索结构

| 层 | 名称 | 是否仿真 | 做法 | 关键开关 |
|---|---|---|---|---|
| Stage 0 | 候选生成 | 否 | **多帧扫描**：`grasp_frame ± span` 的每一帧取该帧 MANO 姿态；每帧配 3×3×3 位置微调 + 绕夹爪 Y/Z 的 ±span° 姿态扰动 | `_STAGE1_MULTIFRAME=1`, `_STAGE1_FRAME_SPAN=15`, `_STAGE1_ROT_SPAN_DEG=5` |
| Stage 1a | 解析预筛 | 否 | `score_grasp_quality()`（antipodal 0.35 + force-closure 0.25 + reachability 0.20 + z-safety 0.20）+ MANO 硬约束 + **手指 OBB vs 障碍物（桌面/邻物）穿透** | `_STAGE1_MANO_REF`, `_S1_CLEAR_REF`, `_S1_COACD_SCREEN`, `_S1_CENTER_MAX_MM` |
| Stage 1b | Top-K 物理验证 | 是 | 取 q_score 最高的 `top_k` 个，各跑一次 `rollout_grasp_only(..., n_frames=160)`（`pd_then_lock`），用 `stage1_reward()` 排序 | `_STAGE1_TOP_K` |
| Stage 1c | CMA-ES 微调 | 是 | 6 维（dx,dy,dz,dry,drx,drz），population 32 × 15 iter，围绕 1b 最优；违反 MANO 硬约束 ⇒ reward = −50 | — |
| Stage 1d | 纯平移精修 | 是 | 旋转锁定，沿夹爪局部 3 轴 ±4mm、步长 2mm 的确定性扫描 | — |
| 验证门 | 3 次独立 rollout | 是 | `lift_final ≥ 3cm`，**≥2/3 通过**才交付；不通过则重跑 CEM（最多 2 轮） | — |

### 3.3 Stage1 的"抓取原语"（固定动作模板）

```
就位(set_qpos，手指张开包住物体) → warmup 5 帧
F0–F19   原地闭合到 q_grasp      （PD 目标，接触后仍保持位置误差 ⇒ 正压力）
F20–F29  维持夹持（等双侧接触建立）
F30–末   竖直提起 20cm（速度自适应，边抬边保压）
```

- 唯一自由度 = `grasp_pose` 本身（位置 + 姿态）。
- **`n_frames=160`**（≈5.3s @30fps）。

### 3.4 `stage1_reward` 的构成（主导项 → 惩罚项）

| 项 | 量级 | 说明 |
|---|---|---|
| 抬升 | `+40 × min(1, lift/0.20)` | **主导**：物体是否跟随夹爪抬满 20cm |
| 入场即接触 | `−80` | `entry_target_contact`：接近段不允许接触 |
| CoACD "会碰物体" | `−80` | `coacd_c_clear_mm > 0` 且 SAPIEN 未报接触时补罚 |
| 抬升前接触 | `−15 × approach_contact_count` | 分阶段精确惩罚 |
| 双侧夹持 | `+6`（lift>5cm 且双侧≥10 帧） | 真抓取 |
| 中心抓取 | `+4·exp(−d/0.02)` | 手指中点到物体中心距离 |
| 姿态/夹持方向 | `+12·align·horiz·(0.25+0.75·down)` | 闭合轴对齐物体**水平最短轴**、且必须水平、且 X 朝下；翻转解清零 |
| 推飞 / 滑落 / 力 sanity | ∓ | 见代码注释 |

### 3.5 当前 Stage1 的**已知断点**（本次会话定位）

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| A | 7533 个候选里**只有 6 个**进入物理验证，且 6 个几乎是同一个位姿 | ① MANO 硬约束写成"相对 **F50** ≤5°"，而多帧扫描的 F35~F65 天然差 >5° ⇒ 全部判违规；② 手指 OBB 穿桌面/邻物再砍一批 | 已加 `_STAGE1_MANO_REF=frame`（相对**该候选自己的源帧**）+ `_STAGE1_TOP_K`。实测 **通过 6 → 1461** |
| B | CoACD 判据对**所有**候选都说"手指必然顶到物体" | `c_clear` 用了**闭合开度**（√ 半间距仅 19.9mm），而物体沿闭合轴半宽 27.5mm ⇒ 恒 >0 ⇒ 判据零区分度 | 已改 `_S1_CLEAR_REF=open`（接近段全开，半间距 65.2mm，与 **Stage2 同源**）。实测 `c_clear` +7.6mm → **−46mm**，κ 0.05 → 0.27~1.0 |
| C | 只改了 `n_frames` / 旋转范围后 Stage1 立刻 0/3 | 桌面几何预筛（`_S1_TABLE_PRESCREEN`，阈值 0.005m + 手指半厚 20mm）在 base_z≈0.046 时把**全部**候选剔除 | 暂用 `_S1_TABLE_PRESCREEN=0` 绕过；**待重新标定**（见 §8） |

### 3.6 设计要点（用户口径）与当前实现的对应关系

> 用户 2026-09-20 口径："夹爪的抓取，需要先有正确的位姿，然后选择其他的位置；
> 而且这个 coacd 每个抓取物体，抓取的效果都不一样的，需要根据被控制物体判断，鲁棒性要强；
> **stage1 的关键就是得到正确的位姿**；stage2 可以长一点，特别是抓取的时候的停顿；
> stage1 没法给出正确的位姿，是很难实现的。"

| # | 设计要点 | 当前实现 | 偏差 / 风险 |
|---|---|---|---|
| 1 | **先有正确的位姿**，再选位置 | Stage0 候选 = 逐帧 MANO 姿态（±span° 扰动）× 位置微调；Stage1c/1d 再微调位置 | ⚠️ "姿态正确"**没有任何硬判据**：只有 reward 软项（`_horiz`/`_flip`/`align`）。今天实测选出的 anchor `闭合轴竖直度=0.70`（上下夹，对齐分 0.037）⇒ **位姿本身就不正确** |
| 2 | 姿态优先、位置其次 | 位置网格 `±10/±8/±5mm`（27 个）与姿态扰动（9 个）**同时**参与，量级相近 | ⚠️ 位置与姿态在候选里"平权"，没有"先定姿态再定位置"的两段式结构 |
| 3 | 每个物体抓取效果不同 ⇒ **按被控物体判断**、鲁棒性要强 | `coacd_key_criteria()` 用**该物体自己的凸包**算 `c_center/c_clear/c_axial` ✓；`q_open` 按物体宽度算 ✓ | ✗ **计量基准不一致**（§8.1：凸包按"当前位姿"读、物心按"加载缓存"减 ⇒ 物体被甩飞后判据虚涨 200mm）；✗ `_COACD_MAX_HULL` 默认 32 而成功运行用 **64**（已写入 `run_config.sh`） |
| 4 | **Stage1 的关键是正确位姿** | Stage1 目前以"能否抬升 20cm"为**主导 reward** | ⚠️ 只看"抬得起"会允许"斜卡/上下夹也能抬"的位姿过关（见 §3.4 gate 3 注释与 §3.6#1） |
| 5 | **Stage2 可以长一点，特别是抓取时的停顿** | `STAGE1_CLOSE = 16` 点（0.53s）+ `STAGE1_SETTLE = 10` 点（0.33s）= **26 点**（`stage1_recipe.py:33-34`）；`_S2_SETTLE_SHIFT` 可整体后移静置窗 | ✓ 可加长（见 §4.1 的旋钮）；⚠️ 改 `close_controls/settle_controls` 会改 recipe ⇒ **必须重跑 Stage1** |
| 6 | 位姿不对，后面都难 | — | ⇒ **优先级**：先把"位姿正确性"变成**硬判据**（闭合轴水平 + 不反向 + 对中），再谈 Stage2 加长与 CoACD 调参 |

### 4.3 接近段避让（N-5，`stage2_approach_opt.py`）

- 在接近轨迹上叠一条横向偏移 `δ(u)`，绕开物体走廊。
- 几何模型：**手指 = OBB（有向盒）**（`_FINGER_HALF_EXTENT=(0.046,0.035,0.0185)`，
  `_FINGER_LOCAL_CENTER=(−0.0045,−0.0302,0.0043)`），物体 = 自身姿态 OBB；
  用 **SAT 带符号分离量** 判定，与物理实测误差 **0.2mm**。
- 基函数 `sin²(πu)`（两端导数为 0 ⇒ 起止速度连续）；代价 = 穿透 + 偏离原轨迹 + 越界。
- 开关 `_APPROACH_OPT`（v1/v2 成功版都是 **0 = 关**）。

## 5. Stage 3：搬运 + 释放

### 5.1 架构要点（v2 的关键修复）

- **单条时间线**：把 Stage2 bundle + Stage3 后缀用 `combine_stage2_stage3()` 拼成一条，
  用同一个循环一次跑完 ⇒ 消除"接续"动作。
  - 旧路径在接续的**第 1 个物理子步**基座角速度飙到 101.587 rad/s（5820°/s）⇒ 物体被甩飞。
  - 开关 `_S3_COMBINED=0` 可回退。
- **源帧线性推进**：`carry_time_scale=1` 时 = 1 源帧/控制点，位置与速度双连续（C1）。
  旧版用 `smoothstep5`（两端导数 0）⇒ 后缀起点速度突降为 0 ⇒ 物体惯性滑脱。
  - 开关 `_S3_CARRY_EASE`（`linear` 默认 / `smooth` 回退）。

### 5.2 相位与门

| 相位 | 说明 |
|---|---|
| `CARRY` | 沿 MANO 搬运（v2：**8 点**） |
| `PRE_RELEASE_SETTLE` / `RELEASE` / `RELEASE_SETTLE` | 释放 |
| `POST_RELEASE_BLEND` / `MANO_FOLLOW` | 释放后回落 |

## 8. 我认为可能有问题的地方（按严重度）

### 8.1 ★【更正 + 真因】CoACD 计量**基准不一致**（物体没复位就换物心），不是缓存污染

> ⚠️ **2026-09-20 更正**：本文档初版把 `_COACD_MAX_HULL=64` 那份缓存判为"污染"，**结论错误**。
> 用户指出"那现在这个用 64 啊"，复核后确认：**64 才是被验证过的那套几何**，真因在**计量基准**。

先给事实（同物体 `glb_4`、`scale=0.5`、同一份 64 凸包缓存 `fbc2248c5fc8e011`）：

| 时刻 | 逐条日志的 `闭合轴范围` | 汇总 `c_clear` | κ 中位 |
|---|---|---|---|
| `output/s1show` 第 1 轮 | `[−18.8, +18.8]mm` ✓ | `−1.17mm`（旧定义/闭合半间距）✓ | 0.40 |
| `output/cctrav3` 第 1 轮 | `[−18.8, +18.8]mm` ✓ | `−46.6mm`（新定义/全开半间距）✓ | 0.54 |
| `output/cctrav3` 第 2 轮 | `[+130.4, +169.2]mm` ✗ | `+112.7mm` ✗ | 0.026 |
| `output/cctrav3` 第 3 轮 | `[+127.8, +166.5]mm` ✗ | `+200.8mm` ✗ | 0.026 |

⇒ **同一份缓存、同一次运行**，第 1 轮正常、第 2/3 轮荒谬 ⇒ 与缓存无关。

**真因**：`score_grasp_quality()` 读的是 actor 的**当前世界位姿**下的凸包 ✓，
却减掉**加载时缓存**的 `self.obj_bbox_centers` ✗。

1. Stage1 验证门不通过会**重跑 CEM**（最多 2 轮），每轮做大量物理 rollout；
2. 失败的 rollout 会把物体**甩飞 13~19cm** ✗；
3. 下一轮开始时**没有任何复位** ⇒ 凸包是"甩飞后的", 物心还是"原来的" ⇒
   `rel = hulls − 过期物心` 把**整段位移**算进了"物体尺寸" ✗ ⇒ `c_clear` 虚涨到 +200mm ✗
   ⇒ κ 从 0.54 崩到 0.026 ⇒ **所有候选被判"会碰物体"** ✗ ⇒ 搜索被毒化 ✗。

**已修（2026-09-20）**：
- `score_grasp_quality()`：以 **actor 当前位姿的平移分量**作物心（与凸包同源同帧 ✓），
  并对"与缓存物心的偏差 > 5mm"打 `WARNING`（漂移立刻可见）；
- 新增 `Stage1Mixin._restore_stage1_object_poses()`，在 **`cem_grasp_pose_optimize()` 开头**
  （即 Stage0 之前）把物体复位到 `_obj_initial_poses`（首次 rollout 前捕获的干净位姿 ✓）
  ⇒ 候选生成与几何判据拿到**同一份干净场景**。

**另外确认**：`_COACD_MAX_HULL` 默认是 **32**，而所有已验证运行用的是 **64**；
它是 **cache key 的一部分** ⇒ 默认值会换一份凸包（现场重分解）✗。
已写入 `run_config.sh`（`export _COACD_MAX_HULL=64`）。

**建议（仍未做）**：缓存 key 里加入**物体名 + 场景 digest**；
加载后断言 `bbox(hulls) ≈ bbox(mesh)`，不符即丢弃重算。

### 8.2 `score_grasp_quality` 硬编码 `'right'`（`stage1_grasp_mixin.py:138`）

```python
mano_f50_pos, mano_f50_R = self._get_mano_f50_pose('right')   # ← 与 --side 无关
```
- `--side left` 时 reachability 项（0.20 分）拿不到 F50（返回 None）⇒ 静默退化为"用物心兜底"。

### 8.3 桌面几何预筛过于保守（`_S1_TABLE_PRESCREEN`）

- 判据 `min(p1_z,p2_z) − 0.020 < 0.005` ⇒ 对"39mm 高、躺在桌面上"的物体，
  几乎所有合理抓取（手指在物心中部 z≈0.020）都被判"会碰桌面"而剔除。
- 实测：`s1horiz` 375 次、`s1rot15` 1831 次踢除 ⇒ Stage1b 全灭（reward 恒 −8）。
- 而 Stage1a **已经**有精确的"手指 OBB vs 桌面 AABB"检查 ⇒ 这层粗筛是**重复且更严**的。
- 建议：删掉粗筛，或把它换成与 Stage1a/N-5 **同一套 OBB 几何**（阈值 = 0 穿透 + 1~2mm 余量）。

### 8.4 多套"翻转/扶正"补丁叠加（姿态一致性风险）

同一个"上下翻转"问题，代码里至少有 6 处独立处理：

| 位置 | 做法 |
|---|---|
| `physics_utils.align_gripper_approach_to_gravity` | X·g<0 ⇒ 绕 Y 翻 180° |
| `physics_utils.unflip_rotation_traj_continuity` | \|X·g\|≤0.15 模糊带内取与上帧更近的分支 |
| `mano_smoothing` 调用上面那个 | — |
| `grasp_hawor` 预处理（帧间 closing 轴 Y 反向 ⇒ 绕 X 转 180°） | 保重力、保 X |
| `stage2_reconstruct_mixin` `_GRIP_FORCE_DOWN=1` | 逐帧"强制朝下" + 以**末帧 Y** 为基准的 roll 归一 |
| `physics_utils` `_GRIP_CLOSE_AXIS_HORIZONTAL=1` | 绕 X 转 θ 让 Y 落进水平面 |

⇒ 这些补丁**互相不知道对方**，且判据/阈值/参考帧各不相同（有的用 F50、有的用末帧、有的用上一帧）。
**"上下翻转问题没解决"的很大一部分原因就在这里**（详见配套文档）。

**★ 并且其中一条根本没接线**（2026-09-20 grep 核实）：
`physics_utils.unflip_rotation_traj_continuity`（专门消除 180° 姿态台阶的那个函数）
只被 `mano_smoothing.smooth_gripper_traj` 调用，而后者只被
`grasp_hawor._smooth_mano_traj()` 调用 —— **该方法全仓没有调用点（死代码）**。
⇒ 当前实际生效的姿态平滑只有"重定向前对 MANO 关节做 SG(17,2)"，
**重定向之后（重力对齐/SVD 定符号之后）没有任何姿态连续性修正**，
180° 台阶原样进入 Stage2 的 `MANO_FOLLOW`（实测 rot 峰值 169°）。
